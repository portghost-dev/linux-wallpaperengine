# Fork capability map

**What this is.** A complete, code-grounded map of everything this fork adds or changes
relative to upstream [Almamu/linux-wallpaperengine](https://github.com/Almamu/linux-wallpaperengine)
at base commit `b016d7d`. It exists so that upstream maintainers and other developers can
see every capability at a glance, find its code in under a minute, and judge what it would
take to cherry-pick.

**How it was made.** Every claim in this document was produced by reading the fork's actual
source and diffing it against the upstream base. Every claim carries a `file::token` anchor
into the publication tree.
Anything that could not be determined from code is explicitly marked **Uncertain**. Where a
code comment and the code disagreed, the code won and the disagreement is noted.

**Conventions.** All paths are relative to the repository root. Anchors (`File.ext::token`: a symbol, env var, or log tag in the named file) refer to this
repository's tree. "Upstream" means commit `b016d7d`. `src/External/` is vendored
third-party code and out of scope except where the build wires it in.

## The shape of the delta

- ~135 upstream files modified, plus two whole new engine directories
  (`src/WallpaperEngine/Api/`, `src/WallpaperEngine/WebHelper/`) and ~34 other new engine
  files (new render objects, mip residency, overlay label, animation timeline, instrument
  registry, localStorage, pointer gate, null audio driver, sha256, new binaries:
  `lwe-web-service`, `lwe-web-helper`, `lwe_bc7enc`, the web-frame probe tool).
- The entire `lwe-ui/` control panel is fork-new (upstream has no UI component).
- Vendored dependencies under `src/External/` (previously upstream submodules, plus the fork-added
  ISPCTextureCompressor) are third-party code and not counted.

## The one-paragraph version

The fork does four big things. (1) It turns the engine into a **daemon**: a same-uid-only
Unix socket speaks a validated 25-verb JSON protocol (`show`, `rotate-set`, `next/prev`,
`set-*`, `release/acquire-outputs`), the Wayland event loop is rebuilt around a bounded
`poll()` that services commands even when no frames render, output lifecycle is a
state machine driven by a deadman switch, fullscreen policy, a running-apps rule, and
explicit verbs, and the daemon persists its own state and restores it on boot so a
restart needs no client. (2) It
**removes CEF from the engine process**: web wallpapers run in a supervised
`lwe-web-service` binary that exists only while a web wallpaper does, with frames crossing
a versioned shared-memory ring. (3) It closes a large slice of **rendering parity**:
scene lighting with shadow mapping, 3D model objects, skeletal puppet animation, particle
child systems and events, perspective cameras, fog, HDR bloom - features
upstream stubs or drops. (4) It makes the engine **cheap to run all day**: FBO pooling,
coverage-sized composites, mip-residency capping, offline BC7 texture compression,
lazy audio, and a stop-the-engine policy for fullscreen or listed apps that hands back
all of it. On top of all of it sits `lwe-ui/`,
a control panel (a small resident tray process plus an on-demand window) that is the
daemon API's reference client.

# 1. Daemon mode and the command API


### Unix-domain command socket (transport layer)
- **What it does**: A non-blocking AF_UNIX/SOCK_STREAM server that accepts line-framed requests and writes line-framed replies on the same connection. `listen()` doubles as a single-instance guard: an existing socket file is probed with `connect()` - a live listener means refusal to start (never unlinking a live instance's socket), only `ECONNREFUSED` is treated as a stale file and removed (CommandServer.cpp::listen). `drain()` accepts all pending connections and buffers partial lines per client until newline; CRLF tolerated, blank lines ignored (CommandServer.cpp::drain). `respond()` retries a wedged reader in 50 ms poll slices up to a 500 ms total budget, then drops the client so a slow reader can never hang the render loop (CommandServer.cpp::respond).
- **Where it lives**: fork-only new file `src/WallpaperEngine/Api/CommandServer.{h,cpp}`; destructor closes all fds and removes the socket file only if this instance created it (`m_ownsSocketFile`, CommandServer.cpp::m_ownsSocketFile, flag set at CommandServer.cpp::m_ownsSocketFile).
- **Surface**: default path resolution `$LWE_SOCKET` -> `$XDG_RUNTIME_DIR/lwe/engine.sock` -> `/tmp/lwe-<euid>/engine.sock` (CommandServer.cpp::LWE_SOCKET). Limits: `MAX_LINE_BYTES = 64*1024`, `MAX_CLIENTS = 8` (CommandServer.h::MAX_LINE_BYTES). Backlog = MAX_CLIENTS (CommandServer.cpp::MAX_CLIENTS).
- **Coupling**: fully self-contained module (POSIX sockets + `Log.h`); nothing upstream touched. Lifts alone with its CMake entry (CMakeLists.txt::COMMON_SOURCES) plus the caller hooks in WallpaperApplication.
- **Tests**: `src/WallpaperEngine/Testing/Cases/CommandSocket.cpp` - 8 cases: 0600 socket / 0700 dir perms (CommandSocket.cpp::socketStat), live-instance refusal (CommandSocket.cpp::displace), stale-socket reclaim (CommandSocket.cpp::reclaims), line framing/split-write/CRLF/blank-line (CommandSocket.cpp::drainUntil), 64 KiB overflow drop (CommandSocket.cpp::waitForClients), respond round-trip (CommandSocket.cpp::responds), `fds()` growth (CommandSocket.cpp::waitForClients), `LWE_SOCKET`/`XDG_RUNTIME_DIR` path resolution (CommandSocket.cpp::LWE_SOCKET).

### Socket security model
- **What it does**: Three concentric controls. (1) Directory created `0700` - but only if the server created it, so a custom path in a shared dir isn't rewritten (CommandServer.cpp::listen). (2) Socket bound under `umask(0177)` and then explicitly `chmod 0600` (CommandServer.cpp::listen). (3) Every accepted peer is verified with `SO_PEERCRED` and rejected unless `peer.uid == geteuid()` (CommandServer.cpp::SO_PEERCRED). The same credentials feed an audit trail: `peerDescription()` (CommandServer.cpp::SO_PEERCRED) names the requester (pid + /proc comm), and the engine logs it on every `release-outputs`/`acquire-outputs` - the verbs that blank or restore the desktop. A client that never sends a newline is dropped at 64 KiB buffered (CommandServer.cpp::drain); the 8-client cap refuses further connections (CommandServer.cpp::drain).
- **Where it lives**: same fork-only files as above (`authenticatePeer`, CommandServer.cpp::authenticatePeer; called from `drain` at CommandServer.cpp::authenticatePeer).
- **Surface**: no flags; the security posture is hard-coded. `$LWE_SOCKET` can relocate the socket into a less-safe directory - the 0600 socket mode is then the only filesystem control, because the `0700` directory fix-up applies only to a directory the server created itself (CommandServer.cpp::listen).
- **Coupling**: self-contained; same module as above.
- **Tests**: CommandSocket.cpp perms case (CommandSocket.cpp::socketStat) and overflow-drop case (CommandSocket.cpp::waitForClients). The uid check itself has no test (UNCERTAIN: exercised only implicitly since tests run same-uid).

### Wire protocol + dispatcher (validation layer)
- **What it does**: One JSON object per line: `{"id": int, "cmd": verb, "args": {...}}` (schema documented in CommandDispatcher.h::cmd). `parse()` rejects non-objects, missing/non-integer `id`, missing/non-string `cmd`, non-object `args`, and any verb not in a 25-entry whitelist (Api/CommandDispatcher.cpp::KNOWN_VERBS). Before JSON parsing it scans bracket depth and refuses nesting > 64 to stop stack exhaustion in nlohmann's recursive parser (Api/CommandDispatcher.cpp::parse); JSON is parsed with exceptions disabled (Api/CommandDispatcher.cpp::parse). Background ids must match `[A-Za-z0-9_-]{1,64}` - no dots, no separators, so no wire input can be path-shaped (Api/CommandDispatcher.cpp::validBackgroundId; the rejection deliberately does not echo the value back, Api/CommandDispatcher.cpp::parse). Response builders emit `accepted` / `done(result)` / `failure(id, message)` (Api/CommandDispatcher.cpp::parse).
- **Where it lives**: fork-only `src/WallpaperEngine/Api/CommandDispatcher.{h,cpp}`. Pure parsing/validation, no engine or socket dependency (by design, CommandDispatcher.h::WallpaperEngine::Api).
- **Surface** - the 25 verbs and their validated argument contracts (all bounds enforced in `parse`, `Api/CommandDispatcher.cpp`):
  - `status`, `quit`, `list-objects`, `next`, `prev`, `ping`, `pause`, `resume`, `release-outputs`, `acquire-outputs` - no args.
  - `show` - requires string `args.id` (validBackgroundId); optional `cc` [b,c,s 0..4, hue +/-6.4] (Api/CommandDispatcher.cpp::validateShowArgs), `speed` 0..20 (Api/CommandDispatcher.cpp::validateShowArgs), `properties` <=64 entries, keys `[A-Za-z0-9_]{1,64}`, string values <=256 chars, number/bool/string only (Api/CommandDispatcher.cpp::validateShowArgs), `scaling` stretch/fit/fill/default (Api/CommandDispatcher.cpp::validateShowArgs), `clamp` clamp/border/repeat (Api/CommandDispatcher.cpp::validateShowArgs), `volume` int 0..128 (Api/CommandDispatcher.cpp::validateShowArgs), booleans `audio_processing`/`mouse`/`automute`/`fullscreen_pause` (Api/CommandDispatcher.cpp::validateShowArgs), `fullscreen_behavior` off/pause/stop (Api/CommandDispatcher.cpp::validateShowArgs), `skip_objects` <=256 ints 0..1e6 (Api/CommandDispatcher.cpp::validateShowArgs), `skip_effects` <=64 ints 0..1e7 (Api/CommandDispatcher.cpp::validateShowArgs), `ui_id` string <=128 (Api/CommandDispatcher.cpp::validateShowArgs).
  - `rotate-set` - `entries` <=512, each an object with valid `id` plus the full show vocabulary (Api/CommandDispatcher.cpp::parse); `interval_s` int 15..604800 (Api/CommandDispatcher.cpp::parse); `order` sequential/shuffle/random (Api/CommandDispatcher.cpp::parse); booleans `avoid_repeat`/`enabled` (Api/CommandDispatcher.cpp::parse); `label` <=128 (Api/CommandDispatcher.cpp::parse).
  - `set-skip` - `ids` <=256 ints 0..1e6 (Api/CommandDispatcher.cpp::parse). `set-fps` - int 1..480 (Api/CommandDispatcher.cpp::parse). `set-speed` - 0..20 (Api/CommandDispatcher.cpp::parse). `set-tuning` - at least one of `classic_k`/`classic_exp`/`audio_gain`/`audio_smooth`, finite (Api/CommandDispatcher.cpp::parse). `set-volume` - int 0..128 (Api/CommandDispatcher.cpp::parse). `set-mouse`/`set-audio`/`set-parallax`/`set-particles` - bool `enabled` (Api/CommandDispatcher.cpp::parse). `set-instrument` - string `name` + bool `enabled` (Api/CommandDispatcher.cpp::parse). `set-fullscreen-ignore` - `app_ids` <=128 non-empty strings <=128 chars (Api/CommandDispatcher.cpp::parse). `set-fullscreen` - `behavior` in off/pause/stop, required because the handler indexes it directly (Api/CommandDispatcher.cpp::parse). `set-app-conditions` - required `behavior` off/pause/stop, optional `names` <=128 strings of 1..64 chars, matched literally against `/proc/PID/comm` (Api/CommandDispatcher.cpp::parse).
- **Coupling**: self-contained (depends only on nlohmann/json). Lifts alone.
- **Tests**: `src/WallpaperEngine/Testing/Cases/CommandDispatcher.cpp` - 11 cases covering valid parses (Cases/CommandDispatcher.cpp), malformed-input rejections with parseable JSON error bodies (Cases/CommandDispatcher.cpp), id echo/null (Cases/CommandDispatcher.cpp), hostile path-shaped ids incl. `../../etc/passwd`, `$(rm -rf ~)`, 65-char overrun (Cases/CommandDispatcher.cpp), cc/speed bounds (Cases/CommandDispatcher.cpp), properties validation incl. the 64-entry cap (Cases/CommandDispatcher.cpp), show-requires-id (Cases/CommandDispatcher.cpp), set-skip/skip_effects (Cases/CommandDispatcher.cpp), show vocabulary (Cases/CommandDispatcher.cpp), rotation/transport verbs incl. set-fps and set-fullscreen edge values (Cases/CommandDispatcher.cpp), and response-builder shapes (Cases/CommandDispatcher.cpp).

### Accepted-then-done command handling
- **What it does**: Short commands reply once with `done`; long commands (`show`, `next`, `prev`) reply `accepted` immediately, then `done` or `failure` with the same id when the multi-second scene rebuild finishes, so clients can distinguish "never heard you" from "working on it" (schema comment, CommandDispatcher.h::show). The dispatch point is `processApiRequests()` -> `CommandDispatcher::parse` -> `handleApiCommand` (WallpaperApplication.cpp::handleApiCommand); parse rejections get the errorResponse written straight back; after every mutating verb the drain loop re-persists the runtime state (WallpaperApplication.cpp::processApiRequests). Every handler branch responds; a final catch-all answers "verb accepted but not implemented" if the whitelist and the handler chain ever drift (WallpaperApplication.cpp::accepted).
- **Where it lives**: modified upstream `WallpaperApplication.cpp`: `handleApiCommand` WallpaperApplication.cpp::handleApiCommand; ack sites at WallpaperApplication.cpp::handleApiCommand (next/prev) and WallpaperApplication.cpp::apiShow (show).
- **Coupling**: deeply woven into WallpaperApplication - every handler reads/writes `m_context.settings`, `m_renderContext`, `m_fullScreenDetector`, or the instrument registry. See per-verb notes below.

### `show` - all-outputs hot swap with rollback and history
- **What it does**: Resolves the id against `$XDG_DATA_HOME/lwe/wallpapers`, `$HOME/.local/share/lwe/wallpapers` (both requiring `<id>/project.json`), then Steam workshop app 431960 - never a raw path (`resolveLibraryBackground`, WallpaperApplication.cpp::resolveLibraryBackground). Preflights by parsing project.json leniently and requiring `type`+`file` (WallpaperApplication.cpp::preflightWallpaper), re-acquires outputs if released, makes any viewport current, acks, then `applyShowCore` (WallpaperApplication.cpp::applyShowCore): clears skip-sets, applies args (cc, speed, properties, volume/audio/mouse/automute, fullscreen policy, scaling/clamp written into per-screen maps BEFORE rebuild because they key mirror groups, WallpaperApplication.cpp::applyShowCore), assigns the new path to every non-span screen, and rebuilds everything via `rebuildForCurrentBackgrounds` (WallpaperApplication.cpp::rebuildForCurrentBackgrounds: clearWallpapers -> clear projects -> evict sole-owner texture cache -> loadBackgrounds -> setupProperties -> ensure browser/audio per project -> buildWallpapers -> `malloc_trim`). On exception it restores 12 previous settings and rebuilds the old set (WallpaperApplication.cpp::applyShowCore). Success pushes the previous full show record (id + ui_id + args) onto a 20-deep history deque (WallpaperApplication.cpp::applyShowCore) and stamps `m_currentShow` with the opaque `ui_id` echo (WallpaperApplication.cpp::applyShowCore). A manual show restarts the rotation countdown (WallpaperApplication.cpp::apiShow).
- **Where it lives**: modified `WallpaperApplication.cpp`: `apiShow` WallpaperApplication.cpp::apiShow, `applyShowCore` WallpaperApplication.cpp::applyShowCore, `rebuildForCurrentBackgrounds` WallpaperApplication.cpp::rebuildForCurrentBackgrounds, `resolveLibraryBackground` WallpaperApplication.cpp::resolveLibraryBackground. Launch defaults snapshot `m_showDefaults` captured in ctor (WallpaperApplication.cpp::m_showDefaults); omitted args fall back to it, not to current values.
- **Coupling**: deeply woven - touches loadBackgrounds (now skips screens with empty path when no defaultBackground, WallpaperApplication.cpp::loadBackgrounds), preset/dependency resolution in `loadBackground` (WallpaperApplication.cpp::loadBackground, project.json without `type` but with `dependency` recursively loads the base, depth-capped at 4, then applies `preset` property overrides), `buildWallpapers` mirror-group keying (WallpaperApplication.cpp::buildWallpapers), `parseLenient` JSON (also in preflight and ApplicationContext config load), and `RenderContext::evictUnusedTextures`. A porter needs the whole rebuild chain, not just `apiShow`.
- **Tests**: none directly (dispatcher-side arg validation only).

### Rotation-set model (`rotate-set`, `next`, `prev`, timed advance)
- **What it does**: `apiRotateSet` (WallpaperApplication.cpp::apiRotateSet) replaces the whole set; `enabled` requires entries non-empty (WallpaperApplication.cpp::applyRotateSet). Disabling freezes the countdown (`frozenRemainingSeconds`); re-enabling the SAME set (same display-id list + interval) resumes the clock via a backdated `lastShow` rather than insta-rotating (WallpaperApplication.cpp::applyRotateSet). Picking: `sequential` walks an index, `random` is uniform, default `shuffle` exhausts a full permutation before reshuffling (WallpaperApplication.cpp::apiRotationPick); `avoidRepeat` (default true, WallpaperApplication.cpp::applyRotateSet) re-rolls up to 8 times against the current display id, where display id = `ui_id` when present so presets sharing a base wallpaper still count as distinct (WallpaperApplication.cpp::apiRotationPick). The next pick is pre-drawn (`apiRotationPredraw` WallpaperApplication.cpp::apiRotationPredraw) so `status.rotation.next_up` can name it (WallpaperApplication.cpp::apiStatus). `tickApiRotation` (WallpaperApplication.cpp::tickApiRotation) advances when the interval elapses (and persists the runtime state on success), skips entirely while outputs are released (clock keeps counting; overdue advance fires on first tick after acquire), and re-arms a full interval on failure. Advance tries each entry up to set-size attempts, skipping entries that fail resolve/preflight/apply (WallpaperApplication.cpp::apiRotationAdvance). `next`/`prev` are manual transports: ack-then-done, `prev` pops history (never re-pushes) and applies with `recordHistory=false` (WallpaperApplication.cpp::handleApiCommand); prev fails cleanly on empty history (WallpaperApplication.cpp::handleApiCommand).
- **Where it lives**: state struct `m_apiRotation` + `m_showHistory` + `m_currentShow` in WallpaperApplication.h::m_apiRotation; logic in WallpaperApplication.cpp as cited.
- **Coupling**: sits entirely on top of `applyShowCore`/`resolveLibraryBackground`; self-contained given those.
- **Tests**: dispatcher-shape only (Api/CommandDispatcher.cpp::parse).

### Output release/acquire, deadman switch, fullscreen-stop gate
- **What it does**: A `ReleaseReason { Live, Verb, Deadman, Fullscreen, AppCondition }` state machine (WallpaperApplication.h::ReleaseReason). `apiReleaseOutputs` (WallpaperApplication.cpp::apiReleaseOutputs) tears down GL first while a surface still holds the context current (scenes, decoders, cached textures die -> VRAM freed), then asks the driver to destroy layer surfaces; failure rebuilds and reports. Idempotent, and a Verb hold cannot be downgraded to Deadman (WallpaperApplication.cpp::apiReleaseOutputs). After a successful release, `evictResidentPages` (WallpaperApplication.cpp::evictResidentPages) trims the heap and `MADV_DONTNEED`s every fully-CLEAN read-only private file mapping, so a released engine's RSS drops to skeleton size (~60 MB) instead of parking hundreds of MB of resident-but-reclaimable library pages; only mappings with zero dirty bytes are dropped (RELRO segments are read-only yet hold relocated data - dropping one is a crash), and the pages refault from page cache on acquire. `apiAcquireOutputs` (WallpaperApplication.cpp::apiAcquireOutputs) re-creates surfaces then rebuilds wallpapers. `tickDeadman` (WallpaperApplication.cpp::tickDeadman): if a ping was ever seen, and BOTH no ping and no render for `m_deadmanSeconds`, it releases outputs (orphan reflex); a failed release re-arms by faking a ping. A `ping` (WallpaperApplication.cpp::handleApiCommand) refreshes the heartbeat AND re-acquires outputs if the hold is Deadman - explicitly why Verb holds can't be downgraded. `tickFullscreenGate` (WallpaperApplication.cpp::tickFullscreenGate): when live policy is `FullscreenBehavior::Stop` and the detector reports fullscreen, shed outputs; re-acquire the moment it clears; never touches Verb/Deadman holds. `tickAppCondition` (WallpaperApplication.cpp::tickAppCondition): a 3-second `/proc/PID/comm` poll for the running-apps rule (`set-app-conditions`, names + off/pause/stop) - pause drives timescale 0 and restores the prior speed, stop releases with reason `app` and re-acquires when no listed process remains; each mechanism only undoes what it engaged. `processApiRequests`, the four policy ticks (fullscreen gate, app condition, rotation, deadman), the property-reload check, the boot-survival mark, and the web-helper pump all run at the top of every main-loop pass in `show()` (WallpaperApplication.cpp::show), before `render()` - so commands are serviced even while paused or released.
- **Where it lives**: WallpaperApplication.cpp as cited; driver half below.
- **Surface**: `m_deadmanSeconds` default 300 (WallpaperApplication.h::m_deadmanSeconds), overridden by `$LWE_DEADMAN` (0..86400; 0 disables, WallpaperApplication.cpp::LWE_DEADMAN). Verbs `release-outputs`/`acquire-outputs` (WallpaperApplication.cpp::handleApiCommand), `ping`, `set-fullscreen` (WallpaperApplication.cpp::handleApiCommand, updates both live settings and `m_showDefaults` so later shows don't resurrect the old policy), `set-app-conditions` (WallpaperApplication.cpp::handleApiCommand; conditions persist with the runtime state). `FullscreenBehavior` enum in ApplicationContext.h::Stop; default `Pause` (ApplicationContext.h::FullscreenBehavior in fork's designated init); `--no-fullscreen-pause` now also writes `fullscreenBehavior = Off` (ApplicationContext.cpp::FullscreenBehavior); `--daemon` defaults `Stop` - the engine owns the policy; persisted state and verbs override (ApplicationContext.cpp::Stop).
- **Coupling**: requires the two new `VideoDriver` virtuals (`releaseOutputSurfaces`/`acquireOutputSurfaces`, default `false` - VideoDriver.h fork addition) and the pause-policy rewiring in `render()` (WallpaperApplication.cpp::m_manualPauseRequested: pause decision now gates on `fullscreenBehavior == Pause`, live and per-frame, plus `m_manualPauseRequested`; upstream's `render()` had no policy gate, and `pauseOnFullscreen` only chose the driver once at startup).
- **Tests**: dispatcher-shape only (Api/CommandDispatcher.cpp::parse) for release-outputs/acquire-outputs/ping/set-fullscreen; no behavioral coverage of the release, acquire, deadman or fullscreen-gate logic itself.

### Runtime state persistence + crash-loop guard
- **What it does**: Every mutating verb re-persists the durable runtime state - current show (id, ui_id, full args), the rotation set with per-entry args, pause, fps, volume, audio/mouse/parallax/particles toggles, speed, color correction, fullscreen policy + ignore list, tuning globals, and the app conditions - to `$XDG_STATE_HOME/lwe/engine-state.json` via temp+rename (`persistRuntimeState`, WallpaperApplication.cpp::persistRuntimeState; the drain-loop hook WallpaperApplication.cpp::processApiRequests). Every successful SCHEDULED rotation advance persists too (`tickApiRotation`, WallpaperApplication.cpp::persistRuntimeState), so a crash or restart restores the wallpaper that was actually on screen, not the one at the last verb. An idle daemon boot (`--daemon`, no CLI backgrounds) restores it by replaying the same core paths a client uses - settings writes, `applyRotateSet`, then resolve/preflight/`applyShowCore` (`restoreRuntimeState`, WallpaperApplication.cpp::REFUSED). Boot survival is tracked in `boot-history.json`: each boot appends `survived:false` and flips it after 60 s of uptime (`markBootSurvived`, WallpaperApplication.cpp::markBootSurvived); when the last two recorded boots died young, restore is REFUSED and the engine boots idle, naming the re-arm path (delete the history file) in its log.
- **Where it lives**: fork-only additions to `WallpaperApplication.{h,cpp}`; state dir helper `runtimeStateDir` (WallpaperApplication.cpp::runtimeStateDir) honors `$XDG_STATE_HOME` and never touches `~/.config/lwe` (the panel owns it).
- **Surface**: the state file and `boot-history.json`; no new verbs or env vars. A boot with CLI-specified backgrounds never restores.
- **Coupling**: reads/writes the same members the verb handlers use; portable with the daemon layer as a unit.
- **Tests**: exercised live (restart restores in seconds with zero clients; triple-SIGKILL produces the refusal); no Catch2 case yet.

### Running-apps condition (engine-side)
- **What it does**: `set-app-conditions {names:[/proc comm strings], behavior: off|pause|stop}` arms a 3-second poll of `/proc/PID/comm` (`tickAppCondition`, WallpaperApplication.cpp::tickAppCondition). While a listed process exists: `pause` sets timescale 0 (the master-pause fact) and restores the prior speed on release; `stop` releases the outputs with `ReleaseReason::AppCondition` (status reason `app`) and re-acquires when no listed process remains. Process existence is the only honest signal for windowless CLI processes (a local LLM holding the VRAM is the motivating case). Holds owned by a bench, the deadman, or the fullscreen gate are never stolen; each mechanism only undoes what it engaged. Conditions persist with the runtime state.
- **Where it lives**: handler WallpaperApplication.cpp::handleApiCommand, tick as cited, validation `Api/CommandDispatcher.cpp::parse`, status block `app_condition` (WallpaperApplication.cpp::apiStatus).
- **Surface**: the verb; `status.app_condition {behavior, count, engaged}`.
- **Coupling**: uses the release/acquire machinery and `setTimescale`; needs both.
- **Tests**: exercised live (pause and stop legs against a probe process); no Catch2 case yet. Names match EVERY process comm - clients should send specific names (the kernel caps comm at 15 chars).

### Wallpaper console rate-limit
- **What it does**: `console.log`/`console.error` from wallpaper scripts collapse identical messages to one line per 10 s window, with the suppressed count appended on the next emission (`ConsoleObject.cpp::CONSOLE_SUPPRESS_WINDOW`). A broken wallpaper logging per frame (~540 lines/s measured) previously blew past journald's rate limit and suppressed the engine's own diagnostics. The distinct-message map is capped at 512 and cleared wholesale so a message-varying wallpaper cannot grow it.
- **Where it lives**: `Scripting/ConsoleObject.cpp`, file-local.
- **Surface**: none; behavior only.
- **Coupling**: none. Lifts alone.
- **Tests**: none.

### Poll-based Wayland event loop + API wake-up
- **What it does**: Upstream's blocking `wl_display_dispatch` is replaced by a proper prepare_read/flush/poll/read_events/dispatch_pending cycle (WaylandOpenGLDriver.cpp::POLLNVAL). The poll set is the Wayland display fd PLUS every API fd from `WallpaperApplication::getApiWakeFds()` (WaylandOpenGLDriver.cpp::dispatchEventQueue; app side WallpaperApplication.cpp::getApiWakeFds) - so a socket command wakes the loop even with no frame callbacks arriving. Timeout is bounded always: 100 ms with the API up, 2000 ms without (WaylandOpenGLDriver.cpp::dispatchEventQueue). `POLLERR|POLLHUP|POLLNVAL` on the display fd (dead compositor) requests exit instead of spinning (WaylandOpenGLDriver.cpp::POLLNVAL). Frame callbacks no longer render inline from the listener: the callback just sets `framePending` (WaylandOutputViewport.cpp::framePending) and the dispatch loop renders each pending viewport ONCE per pass (WaylandOpenGLDriver.cpp::dispatchEventQueue).
- **Where it lives**: modified upstream `src/WallpaperEngine/Render/Drivers/WaylandOpenGLDriver.cpp` (`dispatchEventQueue` WaylandOpenGLDriver.cpp::dispatchEventQueue), `WaylandOutputViewport.{h,cpp}` (`framePending` flag WaylandOutputViewport.h::framePending, callback WaylandOutputViewport.cpp::surfaceFrameCallback). New virtual hooks on `VideoDriver.h` (VideoDriver.h::releaseOutputSurfaces in fork). Only the Wayland driver calls `getApiWakeFds` (grep-verified: single call site, WaylandOpenGLDriver.cpp::dispatchEventQueue).
- **Surface**: FPS cap read fresh each pass via `std::max(1, maximumFPS)` (WaylandOpenGLDriver.cpp::dispatchEventQueue) - this is what makes `set-fps` live; the frame-limiter usleep is at WaylandOpenGLDriver.cpp::dispatchEventQueue.
- **Coupling**: confined to the Wayland driver + viewport + the two VideoDriver base virtuals + `getApiWakeFds` on the app. A porter needs those four pieces; the loop is otherwise self-contained.
- **Uncertain**: on X11/GLFW no driver polls API fds, so command latency there depends on that driver's own loop cadence - `processApiRequests` is non-blocking and runs every pass (WallpaperApplication.cpp::processApiRequests), X11/GLFW loop timing is not characterized here.

### Render keepalive + DPMS safety
- **What it does**: `WallpaperApplication::update()` stamps an atomic `m_lastRender` tick on every serviced frame (WallpaperApplication.cpp::m_lastRender). If `secondsSinceLastRender() > 2.0` (WallpaperApplication.cpp::secondsSinceLastRender), the driver re-kicks EVERY viewport in the render set (WaylandOpenGLDriver.cpp::secondsSinceLastRender) - this restarts the frame-callback chain after DPMS-on, hotplug, or a compositor that stopped scheduling callbacks; the always-bounded poll timeout guarantees the check runs (WaylandOpenGLDriver.cpp::dispatchEventQueue). Separately, `makeCurrent` forces `eglSwapInterval(0)` once per surface (WaylandOutputViewport.cpp::makeCurrent) so `eglSwapBuffers` can never block on a DPMS-off output and wedge the single-threaded loop (which would take the command socket down with it - comment in code). Viewports without surfaces drop out of the render set because `WaylandOutput::updateViewports` skips `layerSurface == nullptr` (WaylandOutput.cpp::updateViewports).
- **Where it lives**: WaylandOpenGLDriver.cpp::dispatchEventQueue; WaylandOutputViewport.cpp::swapIntervalConfigured (`swapIntervalConfigured` flag, WaylandOutputViewport.h::swapIntervalConfigured); WallpaperApplication.cpp::secondsSinceLastRender.
- **Coupling**: small and separable - keepalive needs `m_lastRender` stamp + `secondsSinceLastRender`; swap-interval needs the flag + 3 lines in `makeCurrent`.
- **Tests**: none.

## 5-line summary

The fork adds a daemon/command layer: a same-uid-only UNIX socket server (new `src/WallpaperEngine/Api/`, 0600 socket/0700 dir/SO_PEERCRED/single-instance guard) speaking one-JSON-per-line with a strictly validated 25-verb dispatcher (`show`, `rotate-set`, `next/prev`, `ping`, `pause/resume`, `set-*`, `release/acquire-outputs`, `set-app-conditions`) using an accepted-then-done reply pattern. `--daemon`/`--api-socket` flags boot the engine idle (surfaces up, no wallpaper); an idle daemon boot restores its own persisted state (every mutating verb re-writes `$XDG_STATE_HOME/lwe/engine-state.json` atomically; a crash-loop guard refuses restore after two boots that died young) and otherwise awaits `show`, which hot-swaps all outputs with per-show args, rollback, and 20-deep history; a rotation engine (shuffle-permutation/sequential/random, avoid-repeat, freezable countdown) advances on a timer. Output lifecycle is managed by a release/acquire state machine driven by four sources - verb, a ping-fed deadman switch (`LWE_DEADMAN`, default 300 s), a fullscreen-stop gate, and a running-apps rule polling `/proc` - all serviced from the top of the main loop so commands work while parked. The Wayland driver's blocking dispatch is replaced by a bounded poll loop that includes the API fds, renders each callback-signaled viewport once per pass, forces `eglSwapInterval(0)` (DPMS safety), re-kicks rendering after 2 s of silence (keepalive), and implements output hotplug/hot-unplug. Verified by two Catch2 suites (`CommandSocket.cpp`, `CommandDispatcher.cpp`); the engine-side handlers (~1,700 new lines in `WallpaperApplication.cpp`) are deeply woven into settings/rebuild state and are the main cherry-pick cost.

### 1. Three-binary split: engine (no CEF) / `lwe-web-service` (CEF browser process) / `lwe-web-helper` (CEF subprocess host)

- **What it does**: The fork takes CEF entirely out of the engine process. Upstream created `WebBrowserContext` inside `WallpaperApplication` (upstream:`WallpaperApplication.cpp::ensureBrowserForProject`) and linked libcef into `linux-wallpaperengine-lib` (upstream:`CMakeLists.txt::target_link_libraries`). The service is spawned only when a web wallpaper is actually created: `CWeb`'s constructor calls `HelperClient::create` (`src/WallpaperEngine/Render/Wallpapers/CWeb.cpp::create`), which calls `ensureHelper()` -> `spawnService()` (`src/WallpaperEngine/WebHelper/HelperClient.cpp::create`). `WallpaperApplication::setupBrowser` enumerates web wallpapers but deliberately does not start anything (`src/WallpaperEngine/Application/WallpaperApplication.cpp::setupBrowser`).
- **Where it lives**: New files `src/web-service-main.cpp`, `src/web-helper-main.cpp`, all of `src/WallpaperEngine/WebHelper/`. Heavily rewritten upstream files: `WebBrowserContext.{cpp,h}` (constructor now takes `CefMainArgs&`, `SpawnConfig&`, `MediaSource&` instead of `WallpaperApplication&` - `WebBrowserContext.h::WebBrowserContext`), `BrowserApp.{cpp,h}`, `SubprocessApp.{cpp,h}`, `BrowserClient.{cpp,h}`, `RenderHandler.{cpp,h}`, `WPSchemeHandlerFactory.{cpp,h}`. `WPSchemeHandler.{cpp,h}` are byte-identical to upstream (verified by diff).
- **Surface**: Service CLI switches parsed by `SpawnConfig::fromArguments` (`src/WallpaperEngine/WebHelper/SpawnConfig.cpp::fromArguments`): `--lwe-assets-dir=` (required), `--lwe-web-socket=` (required), `--lwe-max-fps=`, `--lwe-protocol=` (required; must equal `PROTOCOL_VERSION` = 1, `Protocol.h::PROTOCOL_VERSION`, mismatch is a hard refuse at `SpawnConfig.cpp::PROTOCOL_VERSION`), and one `--lwe-scheme=<workshopId>=<path>` per wallpaper (`SpawnConfig.cpp::fromArguments`). It is a coherent module but not liftable as a single directory - the factory signature change is the invasive part.

### 3. Message protocol and channel (socket verbs, caps, peer auth)

- **What it does**: Length-prefixed binary protocol over a Unix stream socket. 8-byte `MessageHeader {u32 length, u16 type, u16 flags}` (`src/WallpaperEngine/WebHelper/Protocol.h::MessageHeader`, static_assert 8 bytes). Commands (engine->helper, type < 0x8000): `Create, Resize, MouseMove, MouseClick, InjectProperties, SetProperty, AudioSpectrum, Destroy` (`Protocol.h::MessageType`); events (helper->engine): `FrameReady, PageLoaded, PageFailed` (`Protocol.h::FrameReady`). Encoders at `Protocol.cpp::AUDIO_BANDS`; every payload starts with the `InstanceId`. `PayloadReader` is bounds-checked with a sticky failure flag (`Protocol.cpp::PayloadReader`). Caps: `MAX_PAYLOAD_BYTES` = 1 MiB enforced on receive (`Protocol.h::MAX_PAYLOAD_BYTES`, `MessageChannel.cpp::MAX_PAYLOAD_BYTES`); `MAX_QUEUED_BYTES` = 8 MiB outbound queue, trip closes the channel (`MessageChannel.h::MAX_QUEUED_BYTES`, `MessageChannel.cpp::MAX_QUEUED_BYTES`); create/resize dimensions capped at 16384x16384 and non-zero, enforced helper-side (`Service/HelperServer.cpp::handle`); `AUDIO_BANDS` = 64 fixed (`Protocol.h::AUDIO_BANDS`). Listener: 0700 directory, 0600 socket (umask 0177 + explicit chmod), refuses to steal a live socket (`MessageChannel.cpp::receive`), backlog 1 (`MessageChannel.cpp::receive`), and `accept()` authenticates the peer with `SO_PEERCRED` same-uid check (`MessageChannel.cpp::SO_PEERCRED`). Default socket path: `$LWE_WEB_SOCKET`, else `$XDG_RUNTIME_DIR/lwe/web-<pid>.sock`, else `/tmp/lwe-<uid>/web-<pid>.sock` (`SpawnConfig.cpp::LWE_WEB_SOCKET`). All fds non-blocking with `MSG_NOSIGNAL` (`MessageChannel.cpp::setNonBlocking`).
- **Where it lives**: New files `src/WallpaperEngine/WebHelper/Protocol.{h,cpp}`, `MessageChannel.{h,cpp}`, `SpawnConfig.{h,cpp}`.
- **Surface**: Socket path env `LWE_WEB_SOCKET` read at `SpawnConfig.cpp::LWE_WEB_SOCKET`. Protocol version kill switch: `--lwe-protocol` vs `PROTOCOL_VERSION` (`SpawnConfig.cpp::PROTOCOL_VERSION`).
- **Coupling**: Self-contained module (only dependency: `Logging/Log.h`); primary consumers are `HelperClient` (engine) and `HelperServer` (service), with its headers also included by `web-service-main`, `WebInstance`, and `PropertyClassifier`.
- **Tests**: None of the Catch2 cases exercise the wire format directly; the probe does end-to-end.

### 4. Shared-memory frame transport (double-slot seqlock ring)

- **What it does**: One POSIX shm object per instance per size, named `/lwe-web-<helperPid>-<instanceId>-<generation>` (`FrameContract.h::frameShmName`). Fixed layout: `FrameHeader` (magic `0x4645574C` "LWEF", version 1, geometry, generation, `std::atomic<uint32_t> sequence`) in the first 64 bytes, then 2 BGRA8 slots (`FrameContract.h::BGRA8`). Writer (`FrameWriter`, service side): `allocate()` creates with `O_EXCL`, 0600, bumps generation even on failure, and only releases the old mapping after the new one succeeds (`FrameContract.cpp::FrameHeader`); `publish()` memcpy's into the back slot then a release-store on sequence, and *drops* paints whose size doesn't match the allocation (FrameContract.cpp::FrameWriter). Reader (`FrameReader`, engine side): two-stage map (probe header at 64 bytes, validate magic/version/geometry, then map full size read-only) - all header fields from the other process are validated, never trusted (`FrameContract.cpp::FrameHeader`); `consume()` is latch -> copy live slot -> re-check, max `MAX_READ_ATTEMPTS` = 4, then abandons and keeps the old texture (`FrameContract.cpp::MAX_READ_ATTEMPTS`). The only per-lifecycle socket traffic is the `FrameReady` event announcing a new generation (`Service/HelperServer.cpp::hasUnannouncedGeneration`, emitted once per generation per `WebInstance::hasUnannouncedGeneration`, `Service/WebInstance.h::hasUnannouncedGeneration`); steady-state frames cross zero socket bytes. On the engine side `CWeb::syncFrameReader` maps `frameShmName(helperPid, id, generation)` from the event (`CWeb.cpp::syncFrameReader`).
- **Where it lives**: New files `src/WallpaperEngine/WebHelper/FrameContract.{h,cpp}`. Consumers: `Service/WebInstance` (writer, `WebInstance.h::m_frames`), `CWeb` (reader, `CWeb.h` member `m_frames`), probe.
- **Surface**: None (no env/flags); kill switch is `FRAME_VERSION` mismatch refuse (`FrameContract.cpp::FRAME_VERSION`).
- **Coupling**: Self-contained; liftable alone given `Logging/Log.h`.
- **Tests**: Probe phases [3]-[5] (`tools/web-frame-probe.cpp::runFrameTransportProof`) assert monotonic sequence, non-uniform content, and generation change across resize, and report retry/abandon counters without asserting on them. No Catch2 case.

Moderately self-contained.
- **Tests**: None direct; probe phase [2] (page-loaded within 30 s) covers the load path.

### 6. Load-state tracking, typed property injection, audio spectrum, audio-listener shim

- **What it does**: `BrowserClient` now implements `CefLoadHandler` and records the first main-frame verdict: `OnLoadError` (minus `ERR_ABORTED`) or an `OnLoadEnd` whose URL is a `chrome-error:` document or whose HTTP status is outside [200,400) (status 0 explicitly not a failure) marks the instance failed (`BrowserClient.cpp::OnLoadEnd`). The server polls these flags once per tick and emits `PageLoaded`/`PageFailed` exactly once (`Service/HelperServer.cpp::isPageLoaded`). Engine-side, `CWeb` gates its one-time property injection on `isPageLoaded` (`CWeb.cpp::isPageLoaded`), and a failed instance never reports itself loaded, so injection is never attempted (`HelperClient.cpp::PageFailed`). Properties cross the wire *typed* - Boolean/Number/String `PropertyValue` (`Protocol.h::PropertyValue`), classified once from the parsed model by `PropertyClassifier.cpp::PropertyValue` (color -> "r g b" string, text properties dropped entirely as display-only labels), and rendered into a JS literal calling `window.wallpaperPropertyListener.applyUserProperties` by `WebInstance::renderApplyUserProperties` (`Service/WebInstance.cpp::renderApplyUserProperties`). Audio: the engine sends 64 raw floats every other frame from `recorder.audio64` (`CWeb.cpp::audio64`; `audio64` at `src/WallpaperEngine/Audio/Drivers/Recorders/PlaybackRecorder.h::audio64`), and the helper builds a 128-element `Float32Array` (64 bands written twice) and calls `window.__lweAudioCallback` (`Service/WebInstance.cpp::Float32Array`). - **Where it lives**: New `PropertyClassifier.{h,cpp}`; rewritten `BrowserClient.{cpp,h}` (upstream's was 6 lines, no load handling - verified above); modified `SubprocessApp` (shim); `Service/WebInstance.cpp`; engine-side hooks in `CWeb.cpp::notifyPropertyChanged` and `notifyPropertyChanged` (`CWeb.cpp::notifyPropertyChanged`), called from the property-reload path at `WallpaperApplication.cpp::notifyPropertyChanged`.
- **Surface**: No new flags; framerate for `windowless_frame_rate` is `max(60, settings.render.maximumFPS)` computed engine-side (`CWeb.cpp::framerate`) and trusted helper-side (`WebInstance.cpp::windowless_frame_rate`).
- **Coupling**: `PropertyClassifier` depends on the Data model and on `Protocol.h` for the `PropertyValue` wire type it returns - self-contained otherwise. The CWeb/WallpaperApplication hooks are a few call sites.

### 7. Idle teardown, crash supervision, respawn with state replay, crash-loop guard

- **What it does (service side)**: `HelperServer` exits when the last instance is destroyed and an idle grace elapses: default `DEFAULT_IDLE_EXIT_MS = 1000` ms, overridden by `LWE_WEB_IDLE_EXIT_MS` (read once, `Service/HelperServer.cpp::LWE_WEB_IDLE_EXIT_MS`), timer starts only after an engine has connected at least once (`HelperServer.cpp::updateIdleTimer`), canceled if a new instance arrives in the window (`HelperServer.cpp::updateIdleTimer`). It also exits immediately when the engine disconnects (`web-service-main.cpp::main`, `HelperServer.cpp::tick`, clearing all instances).
- **What it does (engine side)**: `HelperClient` runs a state machine `Idle/Starting/Connected/Draining/Backoff/Cooldown` (`HelperClient.h::Cooldown`). When the replay map empties while connected it enters `Draining` and the helper is expected to idle-exit; after `DRAIN_TIMEOUT_MS` = 8000 ms the client forces the socket closed and escalates `waitpid` to `SIGKILL` (`HelperClient.cpp::DRAIN_TIMEOUT_MS`). An unexpected disconnect while wallpapers are on screen SIGKILLs the child, unlinks orphaned `/dev/shm/lwe-web-<pid>-*` objects (`HelperClient.cpp::reapShmObjects`), and schedules a respawn with doubling backoff 250->5000 ms (`BACKOFF_BASE_MS`/`BACKOFF_MAX_MS`, `HelperClient.h::BACKOFF_MAX_MS`), reset after a 10 s healthy connection (`HEALTHY_CONNECTION_MS`, `HelperClient.cpp::HEALTHY_CONNECTION_MS`). Respawn is driven one attempt per `pumpEvents()` so a crashing helper cannot stall the render loop (`HelperClient.cpp::Cooldown`). On reconnect, `replayState()` re-sends `Create` for every recorded instance and defers properties until the replacement's `PageLoaded`, where the merged inject+set-property state is replayed (`HelperClient.cpp::PageLoaded`). Crash-loop guard: >=4 deaths in 60 s -> 30 s `Cooldown` with the death ring cleared (defaults `HelperClient.h::CrashGuardSettings`; logic `HelperClient.cpp::BACKOFF_MAX_MS`).
- **Where it lives**: `HelperClient.{h,cpp}` (engine), `Service/HelperServer.{h,cpp}` + `web-service-main.cpp` (service).
- **Surface**: `LWE_WEB_IDLE_EXIT_MS` (`HelperServer.cpp::LWE_WEB_IDLE_EXIT_MS`); `LWE_WEB_CRASHGUARD=<deaths>,<windowMs>,<cooldownMs>`, all three or ignored, values validated (`HelperClient.cpp::LWE_WEB_CRASHGUARD`). Connect patience: 200 attempts x 25 ms on first spawn only (`HelperClient.h::CONNECT_ATTEMPTS`, `HelperClient.cpp::ensureHelper`).
- **Coupling**: Self-contained within WebHelper + the one `pumpEvents()` call per frame in `WallpaperApplication.cpp::show`.
- **Tests**: Probe scenarios (a) teardown-to-zero, (b) SIGKILL respawn with property-replay fidelity, (c) crash-loop guard timing, plus orphan/shm hygiene sweeps (`tools/web-frame-probe.cpp::SIGKILL`); `WebHelperStartupCost.cpp` covers the never-spawn invariant.

### 8. CEF external-message-pump integration (wake-driven poll loop)

- **What it does**: The service sets `settings.external_message_pump = 1` (`WebBrowserContext.cpp::external_message_pump`) and drives CEF itself. `BrowserApp::OnScheduleMessagePumpWork` records the next due time (REPLACE semantics) and writes to a non-blocking eventfd (`BrowserApp.cpp::OnScheduleMessagePumpWork`); the eventfd is created before `CefInitialize` and registered via `setPumpWakeFd` (`web-service-main.cpp::setPumpWakeFd`). The main loop polls {connection fd, or listen fd when unconnected, wake fd} with a timeout clamped to `POLL_MAX_MS` = 50 ms and to the idle-exit deadline, pumping `CefDoMessageLoopWork` when due with an 8 ms idle floor (`PUMP_IDLE_FLOOR_MS`) so a quiet browser doesn't spin (`web-service-main.cpp::POLL_MAX_MS`). The in-code comment records why: a fixed-interval pump starved CEF's windowless BeginFrame timer and froze animations (web-service-main.cpp::CefDoMessageLoopWork). SIGINT/SIGTERM set a stop flag (`web-service-main.cpp::requestStop`).
- **Where it lives**: `web-service-main.cpp`, additions in `BrowserApp.{cpp,h}` (`nextPumpDueMs`, `setPumpWakeFd`), `WebBrowserContext.cpp::WebBrowserContext`.
- **Surface**: None.
- **Coupling**: Internal to the new service binary; nothing upstream-shared.

### 10. `CWeb` rewritten as an shm/texture client

### 11. `lwe-web-frame-probe` diagnostics/verification tool

- **What it does**: A standalone BUILD_TESTING-only executable (`CMakeLists.txt::lwe-web-frame-probe`) that acts as a fake engine: spawns a real service via `HelperClient`, then runs one of three proofs - frame transport (default; sequence monotonicity, tear-free reads under a forced writer-lap stall, resize generation change), `--verbs` (per-verb behavioral assertions measured as frame-delta over a quiet baseline with a 0.10 floor: clicks, moves, live set-property typing, audio, resize), or `--lifecycle` (teardown-to-zero, SIGKILL respawn with property replay, crash-loop guard timing, then a census of `/proc` comms and `/dev/shm` for orphans). - **Where it lives**: New file `tools/web-frame-probe.cpp` (1695 lines).
- **Coupling**: None - links only `linux-wallpaperengine-lib`.

### Five-line summary

The fork removes CEF from the engine entirely: upstream's in-process `WebBrowserContext` is replaced by a three-process design where the engine (which no longer links libcef) posix_spawns a new `lwe-web-service` binary on first web wallpaper, and that service owns CEF while a tiny `lwe-web-helper` binary hosts CEF's child processes. Frames travel over a versioned, double-slot seqlock ring in per-instance POSIX shm objects (`/dev/shm/lwe-web-<pid>-<id>-<gen>`) that the engine maps read-only, with control (create/resize/mouse/typed properties/audio/destroy, plus loaded/failed/frame-ready events) over a same-uid-authenticated, permission-pinned Unix socket with 1 MiB payload and 8 MiB queue caps. The `wp<workshopId>` scheme universe is pre-enumerated from the wallpaper library and baked into the hardened spawn config (close-from-3, restored signal mask, protocol-version handshake). Lifecycle is fully supervised: the service idle-exits 1 s after the last instance (`LWE_WEB_IDLE_EXIT_MS`), the engine detects deaths, unlinks orphan shm, replays instance+property state into a respawned helper, and a crash-loop guard (`LWE_WEB_CRASHGUARD`) imposes cooldowns. Coverage is two Catch2 cases proving zero-cost startup for non-web sessions (`WebHelperStartupCost.cpp`) plus a ~1700-line integration probe (`tools/web-frame-probe.cpp`) that measures frame transport, per-verb behavior, respawn fidelity and orphan hygiene; upstream coupling is concentrated in the `CWallpaper::fromWallpaper` signature, `WallpaperApplication` wiring, and a rewritten `CWeb`.

# 3. Render core, VRAM and the texture pipeline


### FBO pooling model (pooled ping-pong composite pairs)
- **What it does**: Layer composite FBOs (`_rt_imageLayerComposite_<id>_a/_b`) are leased from a per-scene pool keyed by `WxH_flags_format` instead of being dedicated per layer (`CScene::leaseCompositePair`, CScene.cpp::leaseCompositePair). FBOs whose names are referenced cross-object (found by `collectSharedComposites` scanning every image's effect targets/sources/binds/overrides, CScene.cpp::collectSharedComposites) stay dedicated, as does the hardcoded bloom composite id (CScene.cpp::m_sharedCompositeIds) id -1 (CScene.cpp::collectSharedComposites). Same-size layers share one a/b pair; `reportPoolHighWater` logs reuse stats (CScene.cpp::reportPoolHighWater). Invisible layers still render when their composite is shared (`isCompositeShared` gate, CImage.cpp::isCompositeShared).
- **Where it lives**: modified `Render/Wallpapers/CScene.{h,cpp}` (CScene.h::m_poolDedicatedCount pool members, CScene.cpp::leaseCompositePair lease) with the sole consumer at `Render/Objects/CImage.cpp::leaseCompositePair`.
- **Surface**: `LWE_FBOPOOL=0` disables pooling (exact legacy per-layer allocation; CScene.cpp::LWE_FBOPOOL; default ON). `LWE_POOL_HWM=1` enables high-water logging (CScene.cpp::LWE_POOL_HWM).
- **Coupling**: Small surface but semantics-touching: three new CScene methods + members, one CImage call site, plus the shared-composite name scan. Pooled FBOs also interact with the composition-subtree render path below. A porter takes CScene pool members/methods + the CImage lease block; the pool is safe to drop entirely (fallback branch is the legacy path).
- **Tests**: none.

### Coverage-sized composite FBOs + output-derived supersample clamp (canvas/view split)
- **What it does**: Layer composite FBOs are sized to the layer's on-screen coverage (`max(authored size, min(|size*scale|, scene dims))`) instead of the authored size (CImage.cpp::LWE_FBOCOVERAGE), so scaled-up layers don't upscale from a tiny FBO. All scene FBO sizes then pass through `CScene::clampToCap` (CScene.cpp::clampToCap), which aspect-preservingly clamps to `largestOutputSize() * LWE_SSFACTOR` (max single-output dimension, not the multi-output span; CScene.cpp::largestOutputSize), with fill/default modes clamped to *cover* the cap and the rest to *fit inside* it. Separately, the fork decouples canvas dims (`m_canvasWidth/Height`, CScene.h::m_canvasWidth) from camera view dims: camera zoom no longer resizes the scene FBO (comment CScene.cpp::dims; `getWidth/getHeight` now return canvas, CScene.cpp::getWidth).
- **Where it lives**: modified `Render/Wallpapers/CScene.{h,cpp}`, `Render/Objects/CImage.cpp` (coverage block CImage.cpp::coverage, effect-FBO clamp at CImage.cpp::clampToCap), `Render/CWallpaper.{h,cpp}` (`clampToCap` virtual default identity at CWallpaper.h::clampToCap; scene FBO clamped in `setupFramebuffers`, CWallpaper.cpp::setupFramebuffers).
- **Surface**: `LWE_SSFACTOR` float, default 1.0, `0` disables the clamp (CScene.cpp::LWE_SSFACTOR). `LWE_NOFBOCOVERAGE` disables coverage sizing (default ON; CImage.cpp::LWE_NOFBOCOVERAGE). `LWE_FBOCOVERAGE` logs coverage upsizes (CImage.cpp::LWE_FBOCOVERAGE).
- **Coupling**: Woven through the render frame: every FBO-creation site (scene FBO, layer composites, effect pass targets via CImage.cpp::clampToCap, composition FBOs) routes through `clampToCap`, and the scaling mode read from `WallpaperState` must agree with the present-pass UV logic. A porter needs CScene's `clampToCap`/`largestOutputSize`/`m_canvas*`, the CWallpaper virtual + setupFramebuffers change, and the CImage coverage block.
- **Tests**: none.

### Composition-layer subtree rendering
- **What it does**: Image layers flagged as composition layers with authored children get a scene-sized `_rt_compositionLayer_<id>` FBO that aliases `_rt_FullFrameBuffer` for their subtree (CImage.cpp::_rt_FullFrameBuffer). `CScene::renderFrame` walks each object's parent chain (`compositionAncestor`), renders the whole subtree into the composite FBO (with optional `glBlitFramebuffer` background copy for `copiesCompositionBackground`), recurses into nested composition layers, then renders the composite itself (CScene.cpp::copiesCompositionBackground, lambda `renderCompositionImpl` at CScene.cpp::renderCompositionImpl). `m_compositionRenderTarget` + `getActiveRenderTarget/resolveRenderTarget` (CScene.cpp::m_compositionRenderTarget) redirect "the scene FBO" references while inside a subtree. `createObject` gained cycle protection (`m_objectsBeingResolved` + RAII guard, CScene.cpp::m_objectsBeingResolved) since dependency/parent cycles now terminate with an error instead of infinite recursion.
- **Where it lives**: modified `Render/Wallpapers/CScene.{h,cpp}` and `Render/Objects/CImage.{h,cpp}` (the CImage side is the other half of the change).
- **Surface**: no dedicated env knobs; honors the existing `render.debug.objectFilter`/`skipObjects` settings (gate `enabledByDebug`, CScene.cpp::enabledByDebug) and `LWE_SKIPGATE=0` to bypass the constructor-time skip gate (CScene.cpp::LWE_SKIPGATE).
- **Coupling**: Deeply woven into `CScene::renderFrame` and `CImage` construction. Cherry-picking means taking the renderFrame restructure plus CImage's composition-FBO/alias logic together.
- **Tests**: none.
- **Uncertain**: exact semantics of `copiesCompositionBackground()` and `isCompositionLayer()` are defined in CImage; only the call sites are checked here, not the predicate bodies.

### HDR bloom ladder
- **What it does**: When `camera.bloom.enabled && camera.bloom.hdr` (CScene.cpp::hdrLadder), the scene FBO switches to `TextureFormat_RGBA16161616f` (m_sceneFormat, CScene.cpp::TextureFormat_RGBA16161616f; CWallpaper.h::m_sceneFormat, consumed at CWallpaper.cpp::setupFramebuffers) and CFBO allocates it as `GL_RGBA16F` (CFBO.cpp::TextureFormat_RGBA16161616f). The fork generates a mip-ladder bloom effect at load: N RGBA16F half-resolution targets `_rt_hdrBloom_1..N` (N = `bloomhdriterations`, clamp 1..12), a prefilter pass with soft-knee blend params + strength normalization `authored/(1+scatter^(N-2))`, down passes, additive up passes with scatter, and a combine pass blending `_rt_imageLayerComposite_-1_a` with level 1 back into `_rt_FullFrameBuffer` (CScene.cpp::TextureFormat_RGBA16161616f). Ladder sizes derive from the largest output, not the canvas (CScene.cpp::largestOutputSize). The effect JSON is injected into the project VFS at runtime (CScene.cpp::getVFS); the materials/shaders (`materials/wpelinux/hdr_*.json`, `shaders/wpelinux_hdr_downsample.*`, `wpelinux_combine_hdr.*`) are injected earlier by `Assets/AssetLocator.cpp::g_TexelSize`, which string-patches `g_RenderVar0`/`g_TexelSize` declarations into material-annotated uniforms. Layer composites also become float under HDR bloom so pre-clamp >1 values survive (`isHdrBloom`, CScene.h::isHdrBloom; CImage.cpp::isHdrBloom). Non-HDR bloom additionally gains `bloomtint` (CScene.cpp::bloomTintVec).
- **Where it lives**: modified `Render/Wallpapers/CScene.cpp` (ctor, ~240 lines), `Render/CFBO.cpp` (RGBA16F allocation), `Render/CWallpaper.{h,cpp}` (m_sceneFormat), `Assets/AssetLocator.cpp` (shader/material VFS injection). Data fields in `Data/Model/Wallpaper.h::bloom`, parsed at `Data/Parsers/WallpaperParser.cpp::parseScene`.
- **Surface**: wallpaper-authored properties: `hdr`, `bloomhdriterations` (default 8), `bloomhdrscatter` (1.619), `bloomhdrfeather` (0.1), `bloomhdrstrength` (2.0), `bloomhdrthreshold` (1.0), `bloomtint` (WallpaperParser.cpp::bloomtint). `LWE_NOBLOOM` env kills all bloom including the HDR ladder (CScene.cpp::LWE_NOBLOOM).
- **Coupling**: Touches CFBO format handling, CWallpaper FBO creation, CScene ctor, CImage composite format, AssetLocator VFS injection, and the Wallpaper data model. A porter needs all six; the ladder itself is confined to the CScene ctor block and could be excised as a unit if the data-model fields come along.
- **Tests**: none.

### BC7/BC4/BC5 texture ingest (offline texcache)
- **What it does**: A standalone encoder shim `tools/texcomp/lwe_bc7enc.cpp` wraps vendored ISPCTextureCompressor: stdin `[u32 w][u32 h][u32 fmt(7=BC7,4=BC4,5=BC5)][RGBA8 pixels]`, stdout raw compressed blocks, edge-replicated padding to 4x4 multiples, BC7 at max quality (`GetProfile_alpha_slow`, lwe_bc7enc.cpp::GetProfile_alpha_slow). Built only on x86-64 when `ispc` is found (CMakeLists.txt::lwe_bc7enc). At texture load, `uploadFromTexcache` (CTexture.cpp::uploadFromTexcache) looks up `$HOME/.local/state/lwe/texcache/<sha256-of-stored-mip0>`: the `.meta` JSON contract is `{"gl": "BC7"|"BC4"|"BC5", "mips": [[w,h,bytes],...]}` and the `.bc` blob is the concatenated mip levels in raster order; eligible formats are ARGB8888->BC7, R8->BC4, RG88->BC5, single-image non-animated textures only (CTexture.cpp::uploadFromTexcache). On hit it uploads via `glCompressedTexImage2D` with mip-residency rebasing applied (startLevel logic, CTexture.cpp::glCompressedTexImage2D); on any mismatch it silently falls back to the normal path.
- **Where it lives**: new file `tools/texcomp/lwe_bc7enc.cpp`; new function in modified `Render/CTexture.cpp`; CMake wiring CMakeLists.txt::lwe_bc7enc (the only `src/External/` entanglement: ISPC kernel compiled from `src/External/ISPCTextureCompressor/ispc_texcomp`).
- **Surface**: `LWE_TEXCOMP=0` disables the cache lookup (CTexture.cpp::LWE_TEXCOMP); `LWE_SRGBALL` also forces fallback (CTexture.cpp::LWE_SRGBALL). Cache location is hardcoded `$HOME/.local/state/lwe/texcache` (CTexture.cpp::uploadFromTexcache).
- **Coupling**: Self-contained on the engine side (one function + one call site at CTexture.cpp::createGL) but depends on the fork's LZ4-retained mip model (`materializeMip`, CTexture.cpp::materializeMip) to hash the stored mip0 bytes, after LZ4 and before any image decode. A porter could lift it with a plain RGBA readback in place of `materializeMip`.
- **Tests**: `lwe-ui/tests/test_texcomp.py` covers the producer side of the cache contract (eligibility, key, blob layout, meta fields, cache-hit no-op, cancellation); the C++ shim and the `CTexture` read path have none.
- **Producer**: `lwe-ui/src/lwe_ui/texcomp.py` writes the cache in-tree. It resolves the `lwe_bc7enc` shim, invokes it per mip level, and writes the `.bc`/`.meta` pair under the same cache root with the same key the engine reads.

### Mip-residency live-cap and demand expansion
- **What it does**: On by default, and disabled by `LWE_TEXDETAIL=full` (MipResidency.cpp::LWE_TEXDETAIL), the fork caps texture uploads so the largest resident mip dimension ~ the largest live output dimension. At scene construction `buildReferenceMap` walks the data-model scene and records a per-texture verdict: cappable only if every consuming pass uses one of six allowlisted shaders (genericimage*, generic4, chroma4) and the object has no animation layers and isn't perspective (MipResidency.cpp::kAllowlist); verdicts are process-global and monotonically demote because the TextureCache outlives scenes (comment MipResidency.cpp::TextureCache). At resolve time `TextureCache` computes `capDim = capDimension(largestOutputDimension(context))` - 0 (full chain) whenever `MipResidency::cappable(filename)` is false, and otherwise queried live from current viewports, hotplug-fresh - and passes it to the new `CTexture` ctor arg (TextureCache.cpp::CTexture). CTexture then skips stored levels above the cap and uploads the remainder rebased to GL level 0 with tightened `GL_TEXTURE_MAX_LEVEL`, on both the raw path (CTexture.cpp::GL_TEXTURE_MAX_LEVEL) and the BC7 texcache path (CTexture.cpp::GL_TEXTURE_MAX_LEVEL). Per frame, `CImage::render` calls `MipResidency::maybeExpand` with the object's on-canvas quad size (CImage.cpp::maybeExpand); a quad exceeding 1.02xcap triggers `expandCappedTexture` -> `CTexture::expandResidency`, which deletes the capped GL object and re-uploads the full chain from retained RAM (MipResidency.cpp::maybeExpand; CTexture.cpp::expandResidency).
- **Where it lives**: new module `Render/MipResidency.{h,cpp}`; wiring in modified `Render/TextureCache.cpp` (TextureCache.cpp::chain), `Render/CTexture.{h,cpp}` (ctor capDimension, startLevel logic), call site in `Render/Objects/CImage.cpp::maybeExpand`, map build in `Render/Wallpapers/CScene.cpp::buildReferenceMap`.
- **Surface**: on unless `LWE_TEXDETAIL=full`, which makes it fully inert (MipResidency.cpp::LWE_TEXDETAIL). `LWE_TEXCAP=<int>=256>` is a test-only cap override (MipResidency.cpp::LWE_TEXCAP). `LWE_MIPRESIDENCY_DEBUG` logs verdicts (MipResidency.cpp::LWE_MIPRESIDENCY_DEBUG). Default cap fallback is 4096 when no live output size is available (MipResidency.cpp::capDimension).
- **Coupling**: The module itself is small and self-contained, but it threads a new ctor parameter through TextureCache->CTexture and relies on retained mip payloads (LZ4) for expansion. The per-frame hook is one call in CImage. Lifting it requires: MipResidency.*, the TextureCache 4-line block, CTexture's startLevel/rebase logic in both upload paths, and the CImage hook.
- **Tests**: none.
- **Uncertain**: expansion deletes and recreates the GL texture object, so holders must re-query ids per bind (the contract at CTexture.h::stream); holders of `GLuint` texture ids outside `Render/` have not all been audited against that swap.

### LZ4-backed RAM slimming of retained pixels
- **What it does**: `materializeMip` (CTexture.cpp::materializeMip) treats `Mipmap::compressedData` (LZ4 block retained by the parser; upstream already kept it for standard .tex, the fork adds the raw-GL path, `Data/Parsers/TextureParser.cpp::compressedData`) as the canonical backing store, decoding on demand. After upload, `slimRetainedPixels` (CTexture.cpp::slimRetainedPixels) frees the uncompressed copy wherever both exist - skipping video-backed textures since the player streams from the retained buffer - so idle RAM holds only the LZ4 blocks, which are what `expandResidency` re-uploads from.
- **Where it lives**: modified `Render/CTexture.cpp` (CTexture.cpp::MipPixels, slim call at CTexture.cpp::slimRetainedPixels); the producer half lives in `Data/Parsers/TextureParser.cpp` (covered separately).
- **Surface**: none (no knobs); logs `LWE-RAMSLIM`.
- **Coupling**: Depends on the retained LZ4 backing (kept by upstream for standard .tex, extended by the fork's parser for raw-GL); without `compressedData` populated it is a no-op.
- **Tests**: none.

### Texture cache eviction
- **What it does**: `TextureCache::evictUnused()` (TextureCache.cpp::LWE_TEXCACHEDUMP) erases every cache entry whose `shared_ptr` use_count is 1 (i.e. the cache is the sole owner), returning the count. Called at two natural quiet points via `RenderContext::evictUnusedTextures` (RenderContext.cpp::evictUnusedTextures): `rebuildForCurrentBackgrounds` after clearing wallpapers (WallpaperApplication.cpp::rebuildForCurrentBackgrounds) and `apiReleaseOutputs` during output release (WallpaperApplication.cpp::clearWallpapers). `RenderContext::clearWallpapers` (RenderContext.cpp::clearWallpapers) supports the same teardown.
- **Where it lives**: modified `Render/TextureCache.{h,cpp}` and `Render/RenderContext.{h,cpp}`; call sites in WallpaperApplication.
- **Surface**: `LWE_TEXCACHEDUMP` logs survivors with refcount (TextureCache.cpp::LWE_TEXCACHEDUMP) plus wallpaper ctor/dtor life logs (CWallpaper.cpp::LWE_TEXCACHEDUMP).
- **Coupling**: Trivially liftable - one method plus three call sites.
- **Tests**: none.

### Camera / projection corrections
- **What it does**: (a) New `setPerspectiveProjection` (Camera.cpp::setPerspectiveProjection) for scenes without an ortho projection block (`isPerspective` = null projection JSON, WallpaperParser.cpp::is_null): Y-flipped `glm::perspective` with clamped near/far, authored eye/center/up as the runtime lookAt, and a separate ortho `m_screenProjection` for screen-space layout, exposed via `getScreenProjection` (Camera.cpp::getScreenProjection) and consumed by CImage/CText (CImage.cpp::getScreenProjection, CText.cpp::getScreenProjection). (b) `setOrthogonalProjection` rewritten (Camera.cpp::setOrthogonalProjection): honors `general.zoom` (view extent = canvas/zoom, zoom<=0 clamped to 1), symmetric +/-halfRange z-range (max(farz,1000)), identity lookAt - dropping upstream's `glm::translate(projection, eye)`. (c) `setScriptedView` (Camera.cpp::setScriptedView) lets scripts override eye/center with NaN/degenerate guards, feeding getEye/getCenter (Camera.cpp::getCenter); called from `Scripting/SceneObject.cpp::setScriptedView`. (d) `getOverrideFov` exposes `perspectiveoverridefov` (Camera.cpp::getOverrideFov; used by CImage.cpp::getOverrideFov and CModel.cpp::getOverrideFov).
- **Where it lives**: modified `Render/Camera.{h,cpp}`; selection logic in `CScene.cpp::setPerspectiveProjection`.
- **Surface**: wallpaper data keys `general.zoom` / `perspectiveoverridefov` / null `general.orthogonalprojection`; `LWE_CAMPROBE` env logs scripted views (Camera.cpp::LWE_CAMPROBE).
- **Coupling**: Camera.cpp is small and liftable as a unit, but consumers (CImage/CText/CModel MVP construction, CScene ctor) must come along; ortho behavior change (zoom, no eye-translate) alters every 2D scene's framing, so it's not drop-in for upstream without the canvas/view split.
- **Tests**: none.

### OverlayLabel debug overlay
- **What it does**: When `LWE_OVERLAY_TEXT` is set, every present pass draws a two-pass (black shadow + white) text label at the top-left of each viewport (OverlayLabel.cpp::LWE_OVERLAY_TEXT). Text is rasterized once with FreeType from a hardcoded DejaVu/Liberation font path list (OverlayLabel.cpp::kFonts) into an R8 texture; init failure is latched so a broken setup never retries per frame (OverlayLabel.cpp::init). GL state (program/VAO/texture/blend) is saved and restored around the draw.

## 5-line summary

The fork turns the render core into a VRAM-conscious pipeline built on retained (LZ4-slimmed) pixel backing: after upload the uncompressed copy is freed and the LZ4 block is the canonical store, serving mip-residency expansion and the texcache hash. Scene rendering is resized end-to-end - canvas/view split, coverage-sized layer composites clamped to output-sizexLWE_SSFACTOR, and a ping-pong composite FBO pool - while an HDR bloom ladder (RGBA16F targets, generated prefilter/down/up/combine passes) replaces the fixed 3-pass bloom when `bloom.hdr` is set. Textures get a capped-mip residency system (on by default, LWE_TEXDETAIL=full opts out) with per-frame demand expansion, plus an offline BC7/BC4/BC5 texcache ingested by a new ispc shim; the CPU texture cache evicts sole-owner entries at rebuild/release points. Camera handling adds true perspective projection, scripted view overrides, zoom-corrected ortho, and a separate screen projection. Everything is env-flag-gated with default-on kill switches (LWE_FBOPOOL=0, LWE_NOFBOCOVERAGE, LWE_SSFACTOR=0, LWE_TEXCOMP=0, LWE_NOBLOOM), but none of it has test coverage, and two `sLog.error` diagnostics in CScene are always-on with no env gate.

### Puppet skeletal animation (PuppetModel)

### Shadow mapping
- **What it does**: A depth-only shadow atlas shared by all lit passes. `CScene::setupShadowStage`/`renderShadowAtlas` (`CScene.cpp::renderShadowAtlas`) lay out a square atlas (grid of feature cells + 2x3 blocks per shadowed point light, CScene.cpp::setupShadowStage) and render each frame; only `CModel` objects cast shadows, via `CModel::renderShadow` (`CModel.cpp::renderShadow`) which lazily builds an inline `#version 330` depth-only program (CModel.cpp::renderShadow) and draws all submeshes with the light VP. # 5. Data layer, binary parsers, filesystem


### Lenient JSON parsing pipeline (`parseLenient`)
- **What it does**: `JSON::parseLenient` first tries a strict nlohmann parse with `ignore_comments=true`; on `parse_error` it retries after blanking out `//` and `/* */` comments (string/escape aware, newlines preserved) and dropping commas whose next non-whitespace char is `]` or `}` (src/WallpaperEngine/Data/JSON.cpp::parseLenient, helpers `stripComments` at JSON.cpp::stripComments and `stripTrailingCommas` at JSON.cpp::stripTrailingCommas). Declared at src/WallpaperEngine/Data/JSON.h::parseLenient. This lets the fork read WE-authored JSON that carries comments and trailing commas, which upstream's bare `JSON::parse` rejects.
- **Where it lives**: modified upstream files src/WallpaperEngine/Data/JSON.cpp / JSON.h. Call sites swapped from `JSON::parse` to `parseLenient`: src/WallpaperEngine/Data/Parsers/EffectParser.cpp::parseLenient, MaterialParser.cpp::parseLenient, ModelParser.cpp::parseLenient, WallpaperParser.cpp::parseLenient, ObjectParser.cpp::parseLenient, plus new recursive particle-child loading that calls it directly at ObjectParser.cpp::parseLenient (particle definition files). It is also used at src/WallpaperEngine/Render/Shaders/ShaderUnit.cpp::parseLenient, src/WallpaperEngine/Application/WallpaperApplication.cpp::parseLenient, src/WallpaperEngine/Application/ApplicationContext.cpp::parseLenient, src/WallpaperEngine/WebBrowser/CEF/WPSchemeHandlerFactory.cpp::parseLenient.
- **Surface**: no flags/env; always on at those call sites. On the fallback path it logs `JSON strict parse failed - retrying with trailing commas stripped (WE-lenient)` (JSON.cpp::parseLenient).
- **Coupling**: low. `parseLenient` is an additive free function; call-site changes are one-liners. A porter needs JSON.cpp/JSON.h plus the call-site swaps they want. `EffectParser::load` and `MaterialParser::load` additionally throw on empty file content (EffectParser.cpp::readString, MaterialParser.cpp::load) - separate micro-hardening, same hunk.
- **Tests**: none in src/WallpaperEngine/Testing/Cases/.
- **Uncertain**: whether every WE file with comments actually parses after stripping (the stripper is hand-rolled); not verifiable statically.

### JSON type-coercion hardening (numeric strings, exception-safe optionals)
- **What it does**: `JSON::coerceNumericString<T>` (src/WallpaperEngine/Data/JSON.h::coerceNumericString) converts string values like `"0.5"`, `"true"`/`"false"` to arithmetic T via `strtod`, rejecting non-finite parses (`inf`/`nan`) so integral casts avoid UB. `require<T>` now tries coercion before the plain get (JSON.h::require). Both `optional<T>` overloads (JSON.h::coerceNumericString and JSON.h::value_or) lost their `noexcept`, coerce numeric strings, and catch conversion exceptions, logging `Ignoring optional value '<key>' of mismatched type` and returning nullopt/default instead of crashing the whole parse.
- **Where it lives**: modified src/WallpaperEngine/Data/JSON.h only.
- **Surface**: none; automatic for every `require`/`optional` call engine-wide.
- **Coupling**: header-only templates, additive; behavior change is global to all JSON consumers. Self-contained to lift, but it changes semantics everywhere it's included (silent defaulting instead of exceptions).
- **Tests**: none directly.

### BinaryReader fail-fast reads + stream-size bounds
- **What it does**: New private `readExact` (src/WallpaperEngine/Data/Utils/BinaryReader.cpp::readExact) throws via `sLog.exception` when a short read occurs, instead of upstream's silent partially-uninitialized buffers. New `remaining()` (BinaryReader.cpp::remaining) reports bytes left (0 for non-seekable streams). `nextSizedString` rejects a declared length larger than `remaining()` before allocating (BinaryReader.cpp::nextSizedString). `nextNullTerminatedString` was rewritten to read byte-wise via `get()` so a missing terminator stops at EOF instead of spinning on an indeterminate byte (BinaryReader.cpp::nextNullTerminatedString). `nextInt` is now implemented as a cast of `nextUInt32` (BinaryReader.cpp::nextInt).
- **Where it lives**: modified src/WallpaperEngine/Data/Utils/BinaryReader.cpp/.h (new members declared at BinaryReader.h::BinaryReader).
- **Surface**: none.
- **Coupling**: same public API, strictly-additive members; all existing callers get hardening for free. Trivially liftable.
- **Tests**: BinaryParserHardening.cpp::truncated (truncated u32 throws, valid u32, unterminated string stops at EOF, oversized sized-string rejected pre-allocation).

### MemoryStream seek bounds
- **What it does**: `seekoff` now computes an absolute target and rejects (returns -1) any seek landing outside `[eback, egptr]` (src/WallpaperEngine/Data/Utils/MemoryStream.h::seekoff), where upstream would `gbump`/`setg` the get pointer out of bounds. - **Coupling**: self-contained streambuf override; lift alone.

### Package (.pkg) parser hardening
- **What it does**: Two new checks in src/WallpaperEngine/Data/Parsers/PackageParser.cpp: after parsing the file list, every entry's `offset+length` must fit inside the remaining payload bytes (PackageParser.cpp::remaining); and the declared file count is capped at `remaining()/12` (minimum entry size) before `reserve()` (PackageParser.cpp::parseFileList), so a hostile header can't trigger multi-GB allocations or out-of-bounds reads.

- **Coupling**: self-contained; depends on `BinaryReader::remaining()` above.
- **Tests**: BinaryParserHardening.cpp::PKGV0001 (well-formed empty package parses; 0xFFFFFFFF count rejected).

### Texture (.tex) parser hardening + raw-GL TEXB0004 variant + lenient flags
- **What it does**: (a) New `validateMipmapPayloadBounds` (src/WallpaperEngine/Data/Parsers/TextureParser.cpp::validateMipmapPayloadBounds) rejects negative sizes, `uncompressedSize > 1 GiB` (`MAX_MIPMAP_BYTES`, TextureParser.cpp::MAX_MIPMAP_BYTES), and payloads larger than `file.remaining()`; called for both the raw-GL path (TextureParser.cpp::validateMipmapPayloadBounds) and the classic path (TextureParser.cpp::validateMipmapPayloadBounds). (b) LZ4 decode must now produce exactly `uncompressedSize` bytes, not merely `>= 0` (TextureParser.cpp::validateMipmapPayloadBounds). (c) Animated textures with zero frames throw instead of dereferencing `frames.begin()` (TextureParser.cpp::begin). (d) New format variant: TEXB0004 containers whose `freeImageFormat` is `FIF_UNKNOWN` are treated as raw-GL textures - header carries `rawGLMipLevels` (capped 1..16, TextureParser.cpp::FIF_UNKNOWN; new field src/WallpaperEngine/Data/Assets/Texture.h::rawGLMipLevels), the declared per-image mipmap count is overridden by `rawGLMipLevels` (TextureParser.cpp::rawGLMipLevels), and each mip reads optional per-mip width/height/flag plus LZ4-or-raw payload (TextureParser.cpp::validateMipmapPayloadBounds). (e) `parseTextureFlags` now masks unknown bits and logs once instead of throwing (TextureParser.cpp::bits) - wallpapers with unknown flag bits (comment cites 0x800000) no longer lose whole objects.
- **Where it lives**: modified src/WallpaperEngine/Data/Parsers/TextureParser.cpp/.h (`parseMipmap` signature gained `imageIndex, mipIndex`, TextureParser.h::parseMipmap) and Texture.h::rawGLMipLevels.

## 5-line summary

The fork's data layer is heavily hardened against malformed content: `BinaryReader` now fails on short reads and bounds-checks lengths against `remaining()`, `MemoryStream` rejects out-of-range seeks, and the package/texture parsers cap counts and sizes before allocating (all covered by the new `BinaryParserHardening.cpp` test). A lenient JSON pipeline (`parseLenient` + comment/trailing-comma stripping + numeric-string coercion + exception-safe `optional`) is wired through every scene/model/material/effect/particle parse path. New readable formats: raw-GL TEXB0004 textures, perspective-projection scenes, `.mdl` model objects, light/shape objects, keyframed `AnimationTimeline` property animations, recursive child particles, fog, and HDR-bloom scene keys - all unsupported upstream. Filesystem-wise, mounting was centralized into `Assets::setupAssetLocator` (mounts every `.pkg`, all effect dirs, and injects synthesized bloom/HDR/shape virtual files into the VFS), package lookup is case-insensitive, directory containment is fixed, and all candidate Steam library workshop roots are probed. Only env knob in this area: `LWE_SHAPES=0` (shapes render by default).

# 6. Script engine

- **What it does**: The fork fixes how native script modules publish their exports. Upstream called `JS_SetModuleExport()` in the module constructor and (incorrectly) `JS_AddModuleExport()` in the init callback; the fork flips this - exports are *declared* with `JS_AddModuleExport()` at construction and *valued* with `JS_SetModuleExport()` inside the init callback, which QuickJS runs at module instantiation. The init callbacks now also locate the module by matching `getDefinition()` against a global registry and throw a ReferenceError if unregistered (WEVector's own init does the same walk but silently returns instead of throwing). A new `WEVector` module adds `vectorAngle2(vec)` (atan2 in degrees) and `vectorAngle3(a, b)` (clamped-acos angle in degrees, zero-safe).
- **Where it lives**: modified `src/WallpaperEngine/Scripting/Modules/MathModule.cpp` (`wemath_init` MathModule.cpp::wemath_init, ctor MathModule.cpp::wemath_init), `Modules/ColorModule.cpp` (`wecolor_init` ColorModule.cpp::wecolor_init, ctor ColorModule.cpp::wecolor_init); new files `Modules/VectorModule.cpp` (`wevector_vectorangle2` VectorModule.cpp::wevector_vectorangle2, `wevector_vectorangle3` VectorModule.cpp::wevector_vectorangle3, `wevector_init` VectorModule.cpp::wevector_init, ctor VectorModule.cpp::wevector_init) and `Modules/VectorModule.h`. Module registered in `ScriptEngine.cpp::m_modules`. `Modules/ScriptModule.{h,cpp}` are unchanged.
- **Surface**: script-visible module names `WEMath` (`smoothStep`, `mix`, `deg2rad`, `rad2deg`), `WEColor` (`rgb2hsv`, `hsv2rgb`, `normalizeColor`, `expandColor`), `WEVector` (`vectorAngle2`, `vectorAngle3`). Unresolvable imports now throw `could not resolve module '%s'` (`ScriptEngine.cpp::JS_ThrowReferenceError`) instead of returning null silently.
- **Coupling**: self-contained. MathModule/ColorModule changes fix the upstream export-ordering defect; VectorModule is two new files plus three lines in `ScriptEngine.cpp` (include ScriptEngine.cpp::VectorModule, construct ScriptEngine.cpp::VectorModule, emplace ScriptEngine.cpp::emplace) and two lines in `CMakeLists.txt`. A porter could take VectorModule alone trivially; the init-callback restructuring is only needed if upstream's export timing actually misbehaves on their QuickJS version.
- **Tests**: none (no scripting cases exist under `src/WallpaperEngine/Testing/Cases/`).

### Script module load pipeline: compile-only eval, pending jobs, `init()` hook, error containment
- **What it does**: `queueScript()` was rewritten from a single `JS_Eval` into a staged pipeline: compile with `JS_EVAL_FLAG_COMPILE_ONLY`, report compile errors with module key, evaluate via `JS_EvalFunction`, drain up to 64 pending jobs, detect rejected evaluation promises, then capture the module namespace via `JS_GetModuleNamespace` and invoke a new `init(value)` export before the first `update(value)`. `logJSException` was hardened: detects value-less exceptions (host callback returned bare `JS_EXCEPTION`), and prints the JS `stack` property when present.
- **Where it lives**: modified `src/WallpaperEngine/Scripting/ScriptEngine.cpp` (`queueScript` ScriptEngine.cpp::queueScript, compile ScriptEngine.cpp::logJSException, job drain ScriptEngine.cpp::logJSException, namespace ScriptEngine.cpp::JS_GetModuleNamespace, init call ScriptEngine.cpp::logJSException; `logJSException` ScriptEngine.cpp::logJSException; `call` helper unchanged at ScriptEngine.cpp::call).
- **Surface**: script-facing contract gains an optional `export function init(value)`. Per-module `update()` exceptions are logged at most 3 times per module key then suppressed (`ScriptEngine.cpp::tick`); the write-back of the update result is wrapped in `try/catch (const std::exception&)` and swallowed (ScriptEngine.cpp::tick). Debug env var `LWE_SCRIPTDBG` (read at ScriptEngine.cpp::LWE_SCRIPTDBG) traces register/skip decisions.
- **Coupling**: contained to `ScriptEngine.cpp`/`ScriptEngine.h`. The error-shape fixes (replacing bare `JS_EXCEPTION` returns with `JS_ThrowTypeError`) span EngineObject/InputObject/SceneObject/ScriptPropertiesObject/VectorAdapter/ScriptableObjectAdapter but are mechanical and independently cherry-pickable per file.
- **Uncertain**: the 64-job drain cap silently drops further pending jobs; no code comment states whether that bound was measured.

### Degrees<->radians bridge for `angles_*` scripts
- **What it does**: WE script-space angles are degrees; the engine stores radians. For any script module whose key starts with `angles_` and whose value is a Vec3, the engine creates a persistent `degreesMirror` DynamicValue; each tick it refreshes the mirror from radians, hands the *mirror* to `init()`/`update()` (so linked vector args write through in degrees), and converts the result back with `glm::radians` before storing.
- **Where it lives**: `ScriptEngine.h` `LoadedModule::degreesMirror` ScriptEngine.h::degreesMirror; `ScriptEngine.cpp` mirror creation ScriptEngine.cpp::degreesMirror, queueScript store-back lambda ScriptEngine.cpp::degreesMirror, tick bridge ScriptEngine.cpp::degreesMirror.
- **Surface**: triggered purely by the property key prefix `angles_` (ScriptEngine.cpp::queueScript). Trace env var `LWE_LIGHTDUMP` dumps angles for keys containing `angles_112` every 90 ticks (ScriptEngine.cpp::tick).
- **Coupling**: self-contained in ScriptEngine, but depends on the upstream-unchanged script-key naming convention (`angles_<objectId>`); a porter must confirm key generation matches. Logic lives entirely in queueScript/tick.
- **Uncertain**: the `LWE_LIGHTDUMP` trace hardcodes the substring `angles_112`, so it traces one specific wallpaper's property keys rather than a general mechanism.

### Per-frame tick model
- **What it does**: `CScene::renderFrame` calls `getScriptEngine().tick()` once per rendered frame, before `tickAnimations()` (`src/WallpaperEngine/Render/Wallpapers/CScene.cpp::getScriptEngine`). Tick order: (1) `EngineObject::tick()` - refresh registered audio buffers, then fire due intervals/timeouts (`EngineObject.cpp::JS_Call`); (2) `dispatchCursorEvents()`; (3) per loaded script module, set `m_runningModule`, call `update(value)`, write result back. Interval/timeout callbacks are invoked with `JS_Call` and their results are **not** exception-checked (`EngineObject.cpp::JS_Call`).
- **Where it lives**: `ScriptEngine.cpp::LWE_LIGHTDUMP` (tick), `EngineObject.cpp::tick` (timer tick); call site `CScene.cpp::getScriptEngine`.
- **Surface**: none (no config). `g_Time - g_TimeLast` drives animation timing; `engine.frametime` now clamps non-positive deltas to 1/60 (`EngineObject.cpp::engine_get_frametime`).
- **Coupling**: tick itself is upstream structure; the fork inserts one line (`dispatchCursorEvents()` at ScriptEngine.cpp::dispatchCursorEvents) and the angles bridge. A porter wanting only cursor events can take dispatchCursorEvents + one call-site line.
- **Uncertain**: exceptions thrown inside `setInterval`/`setTimeout` callbacks are never retrieved (`JS_Call` result discarded, no `JS_GetException`) - this may leave a pending exception that surfaces in an unrelated later call. Behavior not verifiable statically beyond noting the missing check.

### Audio response buffers (`engine.registerAudioBuffers`)

- **Tests**: none.

### Native persistent `localStorage`

### Cursor event system (`cursorEnter/Leave/Move/Down/Up/Click`)
- **What it does**: After a module is evaluated, the engine scans its namespace for any of the six cursor hook exports; if found, the module is flagged `cursorEvents`. - **Where it lives**: `ScriptEngine.h` (`LoadedModule::{object,cursorEvents,cursorInside,cursorPressedInside}` ScriptEngine.h::ScriptEngine, decls ScriptEngine.h::dispatchCursorEvents); `ScriptEngine.cpp` (hook scan ScriptEngine.cpp::LWE_CURSORDBG, `makeCursorEvent` ScriptEngine.cpp::makeCursorEvent, `dispatchCursorEvents` ScriptEngine.cpp::dispatchCursorEvents, tick call ScriptEngine.cpp::dispatchCursorEvents); hit test `src/WallpaperEngine/Render/Objects/CImage.cpp::LWE_CURSORDBG`.
- **Surface**: script exports `cursorEnter, cursorLeave, cursorMove, cursorDown, cursorUp, cursorClick` (list at ScriptEngine.cpp::CURSOR_HOOKS). Debug env var `LWE_CURSORDBG` (CImage.cpp::cursorLocalPosition) traces exports, probes, edges, and fires. No config keys.
- **Coupling**: needs `LoadedModule` fields, `CImage::cursorLocalPosition` (Render area), `CScene::getMousePositionNormalized` and input context mouse state (both pre-existing). Non-CImage objects never report `inside`, so only image layers get events. Moderately portable: ScriptEngine side is additive; must take the CImage method too.
- **Uncertain**: movement detection uses first-frame `value_or(worldPosition + vec3(1))`, so the very first tick always counts as "moved" - deliberate or not is undeterminable.

### ScriptableObject lifecycle: property registration, animation queue, unregistration
- **What it does**: The base-class ctor no longer registers `origin/scale/angles/visible` from the *group* values (upstream did); per-subclass registrations (e.g. `CImage.cpp::registerProperty`, which existed upstream) now solely govern those names. `registerProperty` still queues the script but now also calls `scene.queueAnimation(value, object)`. ### 4. Audio-processing recorder runtime toggle (script-facing FFT freeze)

- **What it does**: `PlaybackRecorder` gains a public `bool enabled = true` (`src/WallpaperEngine/Audio/Drivers/Recorders/PlaybackRecorder.h::PlaybackRecorder`). Every frame, `AudioDriver::update()` copies `settings.audio.audioprocessing` into it before updating (`src/WallpaperEngine/Audio/Drivers/AudioDriver.cpp::update`). When disabled, `PulseAudioPlaybackRecorder::update()` still drains the pa mainloop but decays all three band arrays toward 0 (`movetowards(..., 0.0f, 0.3f)`), clears `fullFrameReady`, and returns early (`PulseAudioPlaybackRecorder.cpp::fullFrameReady`) - so audio-reactive scripts smoothly settle to silence instead of freezing on the last frame. Band computations were also clamped with `fmax(0.0f, ...)` so bands can't go negative (`PulseAudioPlaybackRecorder.cpp::update`).
- **Stream lifecycle**: `pa_stream_unref` alone leaves a capture stream connected on the server, which keeps its own reference until the stream is disconnected - so every re-take orphaned a live, callback-firing stream until the server ran out of descriptors and destroyed the client. `releaseCaptureStream` detaches both callbacks, disconnects a stream that is ready or still creating, then unrefs it and clears the cached sink name (`PulseAudioPlaybackRecorder.cpp::releaseCaptureStream`). Re-takes are filtered against the live monitor name, so an unchanged default sink no longer replaces a working stream (`PulseAudioPlaybackRecorder.cpp::currentSink`), and `default_sink_name` is null-checked before it reaches `std::string`. A stream that fails is flagged and retried with a bounded backoff (`PulseAudioPlaybackRecorder.cpp::RETRY_DELAY_MAX`), and a feed that stops delivering decays the bands to silence instead of holding the last frame (`PulseAudioPlaybackRecorder.cpp::STARVATION_TIMEOUT`).
- **Capture timing**: the buffer attributes are sized from named millisecond constants (`PulseAudioPlaybackRecorder.cpp::CAPTURE_LATENCY_MS`, `PulseAudioPlaybackRecorder.cpp::CAPTURE_BUFFER_MS`), replacing an upstream expression that divided by 100 where its own comment specified msecs - so fragsize was 100 ms and maxlength 7.6 s rather than the intended 10 ms and 750 ms. `update()` drains every pending fragment per frame instead of dispatching a single iteration (`PulseAudioPlaybackRecorder.cpp::pa_mainloop_iterate`); the read callback already keeps only the newest window, so a queue would be stale by definition and the drain is what stops the shorter fragsize from raising latency instead of lowering it.
- **Where it lives**: modified `PlaybackRecorder.h`, `AudioDriver.cpp`, `PulseAudioPlaybackRecorder.cpp`; setting written by socket verb `set-audio` (`WallpaperApplication.cpp::handleApiCommand`), the `show` arg `audio_processing` (`WallpaperApplication.cpp::audio_processing`), and CLI `--no-audio-processing` (upstream, `ApplicationContext.cpp::loadSettingsFromArgv`).

### 5. Live FFT band dials (`g_LweAudioGain`, `g_LweAudioSmoothMs`)

- **What it does**: Two process-global floats shape the FFT bands. The gain scales every computed band before the destination arrays are written (`PulseAudioPlaybackRecorder.cpp::update`, `f1 *= g_LweAudioGain`); `set-tuning` clamps it to 0.1..20. The smoothing constant governs how the shader-visible arrays approach those destinations: upstream used `movetowards`, a slew limiter that returns the target outright whenever the change is under its cap, so small changes passed through unattenuated and read as flicker once capture was fast enough to resolve them. The live path instead applies an exponential filter whose coefficient is derived from the frame delta, leaving the response independent of frame rate (`PulseAudioPlaybackRecorder.cpp::g_LweAudioSmoothMs`). The decay path still uses `movetowards` because it has to reach exactly zero. Both dials are env-seeded and live-settable.
- **Where it lives**: `extern float g_LweAudioGain` read at `PulseAudioPlaybackRecorder.cpp::g_LweAudioGain`; defined at `src/WallpaperEngine/Application/WallpaperApplication.cpp::LWE_AUDIOGAIN`. `g_LweAudioSmoothMs` is defined alongside it (`WallpaperApplication.cpp::LWE_AUDIOSMOOTH`) and read in the same loop.
- **Surface**: env `LWE_AUDIOGAIN` (default 1.0, clamped 0.1..20 at read, `WallpaperApplication.cpp::LWE_AUDIOGAIN`) and `LWE_AUDIOSMOOTH` (default 90 ms, clamped 0..500 at read, 0 disables smoothing, `WallpaperApplication.cpp::LWE_AUDIOSMOOTH`); socket verb `set-tuning {audio_gain}` / `set-tuning {audio_smooth}` (`WallpaperApplication.cpp::audio_gain`, validated at `Api/CommandDispatcher.cpp::audio_smooth`); status keys `audio_gain` and `audio_smooth` (`WallpaperApplication.cpp::audio_smooth`).
- **Coupling**: the gain is one line in the recorder plus its global; the smoothing is the band loop plus a frame-delta member on the recorder. Both are trivially portable but pointless without the socket unless env-seeding is enough.
- **Tests**: none.

The fork makes audio lazy: a new NullAudioDriver plus a re-bindable `AudioContext::setDriver` means no SDL device is opened until a shown wallpaper actually has sound, and the PulseAudio recorder is likewise upgraded only for audio-reactive projects (`AudioContext.cpp::setDriver`, `NullAudioDriver.cpp`, `WallpaperApplication.cpp::setDriver`). Audio correctness fixes include per-object authored volume mixed in SDL (`SDLAudioDriver.cpp::SDL_MixAudioFormat`, kill switch `LWE_NOOBJVOL`), an output-channel resample fix and a static->per-instance packet cursor in `AudioStream.cpp::resampleAudio`, plus a capture-stream lifecycle that disconnects before releasing so re-takes cannot strand connected streams, a runtime audio-processing toggle that decays FFT bands to zero, a live `audio_gain` dial (`LWE_AUDIOGAIN` / `set-tuning`), a capture path sized in real milliseconds and drained every frame, and band smoothing by an exponential filter rather than a slew limiter (`LWE_AUDIOSMOOTH` / `set-tuning`). Input gains a normalized, presence-aware pointer API (`MouseInput.h::normalized`) with a Wayland global-layout coordinate fix for multi-monitor, and a new self-contained `PointerMoveGate` dedups/suppresses move events to web wallpapers (7 test cases). MPV playback defaults to software decode with capped demuxer/thread/VRAM footprint (env-tunable: `LWE_HWDEC`, `LWE_MPV_DEMUX_MB`, `LWE_MPV_THREADS`, `LWE_MPV_EXTRA_FRAMES`) and supports live playback speed through a new `setPlaybackSpeed` virtual chain. Fullscreen handling becomes a tri-state Off/Pause/Stop policy (`ApplicationContext.h::FullscreenBehavior`): Pause freezes and optionally evicts VRAM, Stop releases outputs entirely, and the ignore list is live-editable via `set-fullscreen-ignore` with detector recount (`WaylandFullScreenDetector.cpp::recomputeRelevance`) - but the policy is deeply woven into `WallpaperApplication`'s render loop and output-release machinery, so only the detector recount and the env-tunable MPV/audio/input pieces are clean cherry-picks.

### 4. Instrument registry (`src/WallpaperEngine/Logging/InstrumentRegistry.{h,cpp}` - fork-only)

- **What it is**: a fixed 3-entry table of runtime-toggleable log gates (`Logging/InstrumentRegistry.cpp::WallpaperEngine::Logging`): `LWE_PARTSTATS`, `LWE_TWINKLEPROBE`, `LWE_ROPETRAILPROBE`. Each entry is `{name, atomic<bool> on, atomic<uint32> epoch}`; lookup is a lock-free `strcmp` scan (`Logging/InstrumentRegistry.cpp::g_entries`).
- **Semantics**: `instrumentSet` bumps the epoch only on an off->on edge (`Logging/InstrumentRegistry.cpp::instrumentSet`); `instrumentSeedFromEnv` seeds initial state from getenv and sets epoch 1 for launch-enabled entries (`Logging/InstrumentRegistry.cpp::instrumentSeedFromEnv`), called once at the top of `WallpaperApplication::show()` (`WallpaperApplication.cpp::instrumentSeedFromEnv`). Consumers poll `instrumentOn`/`instrumentEpoch` per frame and reset latched accumulators on epoch change (`CParticle.cpp::instrumentOn`).
- **Surface**: toggled live via the `set-instrument` socket verb (`WallpaperApplication.cpp::handleApiCommand`); `instrumentsEnabled()` (`WallpaperApplication.cpp::instrumentsEnabled`) feeds status output. Launch-time env vars of the same names still work via seeding. ### 5. Config-file keys

- **`config.json` (Wallpaper Engine's own)**: the fork consumes the **same keys as upstream** - `steamuser` section and playlist entries (`name`, `settings.delay` default 60, `settings.mode` default `"timer"`, `settings.order` default `"sequential"`, `settings.updateonpause`, `settings.videosequence`, `items`) at `ApplicationContext.cpp::parsePlaylistSettings`. ### Engine daemon API client (`api_client`)
- **What it does**: Stdlib-only Unix-socket client for the engine's command API: one JSON object per line, replies correlated by id, in `$XDG_RUNTIME_DIR/lwe/engine.sock`. Short verbs answer once with `status="done"`; `show` answers `accepted` first, then `done` after the scene load. Every call is one bounded connect-send-read (3 s ack timeout, 30 s for `show` done, 64 KiB reply cap); a dead or absent engine returns `None`, never raises (`api_client.py::request`).
- **Where it lives**: fork-only `lwe-ui/src/lwe_ui/api_client.py`.
- **Surface**: env override `LWE_SOCKET` (`api_client.py::LWE_SOCKET`); default socket path (`api_client.py::XDG_RUNTIME_DIR`). Full verb surface the panel can drive, each a thin function:
  - `show` with per-wallpaper resolved args: `id`, `cc` [b,c,s,hue_rad], `speed`, `properties` (PROP_ strings), `scaling`, `clamp`, `volume` 0..128, `audio_processing`, `mouse`, `automute`, `fullscreen_pause`, `fullscreen_behavior`, `skip_objects`, `ui_id` identity echo (`api_client.py::PROP_`)
  - `status` (`api_client.py::status`), `rotate-set` (entries = complete show-args, interval clamped 15..604800 s, order, avoid_repeat, enabled, label <=128 chars) (`api_client.py::rotate_set`), `next`/`prev` ack-only (`api_client.py::next_wallpaper`), `ping` dead-man heartbeat (`api_client.py::ping`)
  - `list-objects` (`api_client.py::list_objects`), `set-skip` (`api_client.py::set_skip`), `set-fps` 1..480 (`api_client.py::set_fps`), `set-speed` 0..20 (`api_client.py::set_speed`), `set-volume` (`api_client.py::set_volume`), `set-app-conditions` (`api_client.py::set_app_conditions`), `set-mouse` (`api_client.py::set_mouse`), `set-audio` (`api_client.py::set_audio`), `set-tuning` partial-update (`api_client.py::set_tuning`), `set-parallax` (`api_client.py::set_parallax`), `set-particles` (rebuilds scene) (`api_client.py::set_particles`), `set-fullscreen-ignore` substring app_ids (`api_client.py::set_fullscreen_ignore`), `set-instrument` (`api_client.py::set_instrument`), `set-fullscreen` off|pause|stop (`api_client.py::set_fullscreen`)
  - Raw `release-outputs` / `acquire-outputs` via `request()` in `bench_courier.py::resume`.
- **Coupling**: Self-contained module; depends only on the fork's engine daemon API existing. Lift-alone = this file plus an engine that speaks the verbs.
- **Tests**: `lwe-ui/tests/test_api_client.py`, `test_api_shownow.py`.
- **Uncertain**: none.

### App shell: entry point, tray, single instance
- **What it does**: `python -m lwe_ui` -> `app.main()`. Two entry paths, one codebase: `--tray` dispatches to `tray.main` BEFORE any heavy import (`app.py::spawn_tray_if_needed`) - the resident tray is its own QML-free, theme-stripped process (`tray.py::QApplication`, menu = pause/resume, next, stop/restore outputs, open panel, exit) that opens the full window as a child process and re-raises a live one over the window's single-instance socket (`tray.py::open_window`). ### 5-line summary
`lwe-ui/` is an entirely fork-added PySide6+QML control panel (`python -m lwe_ui`) that manages a Wallpaper Engine library: browsing, playlists/rotation, per-wallpaper settings with realtime autosave, a test-bench + import wizard for new Workshop items, and a developer debug cockpit. It runs as two processes through one entry point: `--tray` is a small resident tray (icon, quick actions, launcher; no QML - what autostart runs), and the bare command is the full window, which exits on close and returns its memory; the repurposed "minimize to tray when closed" setting decides whether a window close leaves the tray running. It drives the fork engine live over a JSON-lines Unix socket (`$XDG_RUNTIME_DIR/lwe/engine.sock`: `show`, `rotate-set`, `set-speed/fps/volume/skip/tuning/instrument/fullscreen/app-conditions...`). It owns the `lwe-engine.service` systemd user unit and its generated env file, and persists everything under `~/.config/lwe/` (shell-sourceable confs) plus state/data dirs. Coupling to upstream code is zero - it is a separate package whose only dependency is the fork's engine-side daemon API and flags, so cherry-picking it requires the engine daemon work first. Coverage is via ~60 Python test scripts in `lwe-ui/tests/`, not the C++ test tree.

## Tier 3 - deeply woven (take the subsystem or nothing)

- **The daemon command handlers** (`WallpaperApplication.cpp` `handleApiCommand` and
  everything below it: `applyShowCore`, `rebuildForCurrentBackgrounds`, rotation engine,
  release/acquire state machine, deadman, status aggregation - ~1,844 new lines). Every
  handler reads/writes settings, render context, detector, and instrument state. This is
  the single largest porting cost in the fork - but it is also the daemon itself.
- **The lighting stack** (CLight + CScene light/shadow stage + CPass light staging +
  `ShaderUnit::generateLightingV1` + CRenderable virtuals). The GLSL module calls WE's
  own `ComputePBRLightShadow*` from wallpaper shader includes, so it only links in
  shaders that carry WE's lighting headers.
- **The particle rewrite** (`CParticle.{h,cpp}`, ~1,900 diff lines: child systems,
  events, instance overrides, trail ribbons, buffer pooling). `EmitterFunc` signature
  changed; not liftable piecemeal except the small rate/startTime/prewarm gates.
- **Composition-layer subtree rendering** (CScene `renderFrame` restructure + CImage
  composition FBO/alias logic). Must move as one piece.

## What a porter should NOT take

The ~40 pure log-probe env vars (`LWE_*DUMP`, `LWE_*PROBE`, ...) are development
instrumentation; take the 5-6 you need while debugging a port, leave the rest. The
handful of unconditional diagnostics listed in "Known rough edges" should be dropped or
gated in any port.

# 11. Known rough edges

Listed because this document is meant to be honest, and because upstream readers will
find them anyway:

- **Unconditional diagnostics that fire on normal operation** - these look
  like leftover development instrumentation and are candidates for env-gating:
  the `LWE-DEBUG` projection dump in the CScene ctor (`CScene.cpp::DEBUG`, error level),
  `LWE-SCENEFB` for the first 3 frames (`CScene.cpp::SCENEFB`, error level),
  and `LWE-TIMELINE` logged per animated property (`CScene.cpp::TIMELINE`, out level).
  (`LWE-PRESENT` used to be on this list; it is now env-gated behind `LWE_PRESENTTRACE`
  and demoted to out level.)
- **`LWE_LIGHTDUMP` contains a hardcoded wallpaper-specific trace** (`angles_112`,
  `ScriptEngine.cpp::LWE_LIGHTDUMP`).
- **Test coverage is concentrated in the new infrastructure** (command socket,
  dispatcher, binary parsers, instrument registry, pointer gate, web-helper startup).
  The render, scripting, audio, and video chapters have no `Testing/Cases/` coverage;
  behavioral confidence there comes from live burn-in, not the suite.
- **Observation-derived formats**: the MDLV submesh layouts, puppet clip padding, and
  point-light shadow face order are reconstructed from observation, not specs - each is
  marked Uncertain in its chapter. They are guarded against malformed input but their
  native-parity claims rest on measurement, not documentation.
- **`VirtualAdapter::open` returns a shared stream with a shared cursor** - safe only
  because current usage is strictly sequential on one thread.
